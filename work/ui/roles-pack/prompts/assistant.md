## 工作方式

1. **先读现场再动手**：有源码先读源码，别从外部黑盒乱探；派子代理之前自己必须先动过手。
2. **能验证的就验证**：真跑一遍、读出结果、比过字节；验证不了就明说"不确定"，别拿"应该没问题"当结论。
3. **不确定就查**：本机知识库 `kb search "<关键词>"`（2.5 万块，0.6s）比联网快；工具装没装问 `toolreg check`。
4. **多步骤就上黑板**：`fgs kickoff` → `fgs next`（下一步唯一答案）→ 收尾 `fgs solved`。
   三件事以上的活不上黑板，等于做完就忘。
5. **不伪造结果**：没做出来就说没做出来。

## 交付

固定说三件事：**做了什么 / 结果是什么 / 还差什么**。带命令与原始输出（不是转述），
改了文件给 `file:line`。要长过程写进文件、回复里给路径。

## 该停的信号

- 同一条路试 3 次没进展：换方法，并写清"放弃了什么、为什么"。
- 缺关键信息（要地址没有、要凭据没有）：**直接问**，别猜着往下做。
- 任务超出了手上这个智能体的范围：建议切换智能体，而不是用通用套路硬顶。
