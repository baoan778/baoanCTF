# 死路库（`docs/writeups/死路库.md`）—— WP 的「失败与调整」为什么要写判据

> 从 `skills/wp-writer/SKILL.md` 正文搬出来（2026-10-12）：入口超重，细节按需读。

## 它解决什么

手法库管「**该怎么做**」，死路库管「**这条路走不通**」。
难题里最贵、别人最没有的资产就是**已证伪的路线** —— 同一类题的第二道，
可以直接跳掉一整条路线，而不是把前一道的坑重踩一遍。

## 死路怎么进库（三道）

1. **你在 WP 里写**：`## 失败与调整` 每一行 = **路线** + **判据**（复现命令 + 反向输出是什么）+ 黑板上的 `fNNN`。
   写「试了很久没成功」这种**没判据**的句子 ＝ 下一个人读了也不敢信，等于没写。
2. **闸门抽候选**（人审，不自动进库）：

   ```bash
   python3 board/retrospect.py scan     # 死路 = 任何 verified 且命中「证伪/排除/不成立…」的 Fact
   python3 board/retrospect.py --list   # ◆手法 / ✗死路 两类分开标
   python3 board/retrospect.py --merge <id> --reviewer <人名> \
     --generalize "<现象 + 判据：凭什么说它走不通>" \
     --pitfall    "<什么条件下不用再试、该换哪个攻击面>"
   ```

   `kind=deadend` 自动路由到 `死路库.md`（手法仍进 `手法库.md`）；
   审计写进 `docs/writeups/手法库.audit.jsonl`（带 `kind` / `lib` / 覆盖率）。

3. **闭环**：这本库会被 `kb` 索引（`docs/writeups/**/*.md`），并且
   `fgs brief` 会**单独提示**命中的跨题死路给新 Worker
   （`## ⚠ 跨题死路库命中 —— 同类题里已经走过、走不通`）——
   所以新 Worker 起手就看得到，不用自己去搜。

## 两个已知坑（2026-10-12 实测）

- **库头部的「记录格式」示例里也有 `###`** —— 不剥掉 ``` 围栏，它会被当成一条真条目，
  在 `fgs brief` 里冒出一条假命中 `✗ <走不通的路线>（一句话）`。
  代码侧已用 `strip_fences()` 处理（`board/retrospect.py`、`board/fgs.py` 各一份）；
  **你自己写条目时别把示例写在围栏外**。
- **重名/重合门禁是 fail-closed 的**：候选跟正本已有条目有可察觉重合就默认拦下，
  要写必须 `--force-dup`（覆盖率与最像的那条一起进审计）。
  真不同就 `--force-dup`；确实重复就 `--drop <id> --reviewer <人名> --reason …`
  —— **弃用也是结论**，避免它下次又冒出来。
