# WP 生成

## 你的位置

你是一个**旁支代理**。主会话在你干活的时候已经在解下一道题了。
所以你**不要**回来问问题，**不要**等确认 —— 把活干完，交一份文件，回一句话。

> **你被派出来，说明用户已经确认过 flag 正确了**（黑板上有 `confirmed` 记录）。
> 如果 `fgs show` 里看不到 `👍 人工确认`，立刻停下回报 —— 说明闸门没开，不该出 WP。

### 但「已确认」不等于「可以写成大功告成」（平台回执判据）

写结论时按回执实际情况措辞，别替平台背书：

| 图上的状态 | 该怎么说 |
|---|---|
| `confirmed` 且回执是计数式（`correctCount >= totalCount`） | 可以写「全部 flag 已被平台接受」 |
| `confirmed` 但只确认了部分 flag | **写明哪些被接受、哪些待确认**，别把整题写成完成 |
| 只有 `solved`（或无回执） | 只能写「已解出，待平台确认」—— 而且这种情况根本不该出 WP |

**不算回执证据的东西**：agent 自称成功、跑出候选 flag、HTTP 200、退出码 0、「提交成功」字样。
**历史回执要标轮次**：`log.jsonl` 里旧任务的 `confirmed` 不是本次的证明。

## 唯一输入：黑板 + 留档

`<project_id>` 由派你的人给出。你的素材只有这两处，**没有**主会话的对话历史：

```bash
export PATH=$PI_LAB_ROOT/tools/bin:$PATH
cd $PI_LAB_ROOT/work/<project_id>

fgs show     <project_id>      # 人读的图：Goal / Facts / Steps / 关系
fgs snapshot <project_id>      # 机器读的快照
fgs log      <project_id> --tail 100   # 审计流水：谁在什么时候做了什么
ls -la                         # 留档：脚本、产物、原始输出
```

**这就是黑板的全部意义** —— 图是唯一共享真相，所以你可以零上下文接手。
如果图里信息不够还原过程，**如实写"记录缺失"**，不要靠猜把故事补圆。

## 铁律：只写图上有的

| 图上 | 你能写 |
|---|---|
| `verified` 的 Fact | 直接写，但**必须同时贴上支撑它的原始输出**（去留档里找，或重跑一遍命令） |
| `inferred` 的 Fact | 可以写，但**必须显式标注"（推断）"** |
| 图上没有的 | **不许写**。哪怕你从附件看出来是这样，也要标成你的观察，别混进解题过程 |
| flag | 逐字照抄 `verified` Fact 里的原文。**不许凭格式补全、不许改大小写** |

重跑命令验证是**允许且鼓励**的（你有 bash），但别改任何东西 —— 你是记录者不是解题者。

## 输出 1：`docs/writeups/WPs/<project_id>_WP.md`（**WP 统一放这个目录**）

> **骨架见 `references/WP模板.md`**（题目/已知条件 → 关键事实 → 假没 → 步骤 →
> 利用过程 → 失败与调整 → 证据路径 → 结果与验证 → exp → 最终 Flag）。
> 照着填，别改结构；`<...>` 占位符必须全部替换或标「记录缺失」。

## 输出 2：往 `docs/writeups/INDEX.md` 追加一行

```markdown
| <项目id> | <题型> | `<flag>` | <考点一句话> | <关键一步> | [WP](WPs/<项目id>_WP.md) |
```

有表头就对到列上，没有就先写表头。

## 输出 3：`docs/writeups/手法库.md`（**只在真有可复用手法时写**）

这是跨项目的积累 —— 黑板管**这一次**的真相，手法库管**下一次**能直接用的东西。

```markdown
### <手法名>（<适用场景>）
**触发条件**：看到什么信号就该想到它
**做法**：具体步骤 / 命令
**坐实**：★ 用它**真拿到过什么**（flag 原文 / 洞 + 证据文件路径）—— 写不出就标 `未坐实`
**来源**：<项目id>
```

> ★ **「坐实」是硬要求**（Trail of Bits `skills` 的 Trophy Case 纪律）：
> 手法库顶部有一张 **Trophy Case 总表**，你新写的条目要同步补进那张表（只补坐实的）。
> **写不出「坐实」不等于不能写** —— 标 `未坐实` 保留（下次优先试它），但**不许编**。

**宁缺毋滥。** 没有真正可复用的东西就跳过这一份，别往里灌水 ——
灌水的库下次就没人读了。

### 手法库有**两条入径**，别搞混

| 入径 | 谁写 | 写到哪 | 有没有人工闸门 |
|---|---|---|---|
| **a）WP 代理直接写**（本节） | 旁支代理（你） | `手法库.md` | 由本 skill 的纪律约束：只写真正可复用、自己能复现的 |
| **b）自动抽候选 → 人审 → 合并** | `board/retrospect.py` | `手法库.md`（手法）／`死路库.md`（死路） | **有人**：`--merge` 必须 `--reviewer <人名>` |

- 代理写 WP 时走 **a**：图里已经有 verified 结论、你也复现过 → 按上面格式直接追加。
- 如果某题**没有派 WP 代理**、但图上留了有价值的结论 → 走 **b**：
  ```bash
  python3 board/retrospect.py scan        # 从图里抽两类候选：
                                          #   手法 = done Step + verified Fact
                                          #   死路 = 任何 verified 且命中「证伪/排除/不成立…」的 Fact
  python3 board/retrospect.py --list      # 看候选（◆手法 / ✗死路；◆=带结构化 meta，更可能可复用）
  python3 board/retrospect.py --show <id> # 看全文 + 与正本的重合度
  python3 board/retrospect.py --merge <id> --reviewer <人名> --generalize "…"
  #   → 手法自动入 手法库.md；死路（kind=deadend）自动入 死路库.md
  ```

> **死路库是跨题收益最高的一本**（同类题第二道直接跳掉一整条路线）——
> 为什么 + 两个已知坑 → `references/死路库.md`。

**b 的闸门是 fail-closed 的**：候选只要跟正本已有条目有可察觉的重合，默认就拦下 ——
要写必须加 `--force-dup`（会连同覆盖率、最像的那条一起记进
`docs/writeups/手法库.audit.jsonl`）。
这条不是洁癖：实测过三次「换一种说法蒙过自动去重」，每次都真的把重复条目写进了正本。
**弃用候选也要署名**（`--drop <id> --reviewer <人名> --reason …`）—— 弃用也是结论，避免下次再冒出来。

## 反模式

| 反模式 | 为什么错 |
|---|---|
| 把过程写得很漂亮但贴不出原始输出 | 不可复现 = 没有价值。WP 的唯一用途是让别人能重走一遍 |
| 靠推理把缺失的记录补圆 | 你补的是"应该发生的事"，不是"实际发生的事"。标"记录缺失"才是诚实的 |
| flag 从图里抄错一个字符 | 逐字复制，别手打 |
| 往手法库里塞"要注意大小写"这种废话 | 手法库一旦变噪音就没人读了 |
| **自己复现不出来就写结论说原记录错了** | ★ 踩过：代理没复现出 `psm=7`，直接写进手法库说"psm=7 糊、psm=3 对" —— **完全说反了**（真因是它漏了"裁切+放大"这一步，试的是整图）。复现不出来时，先怀疑自己漏了前置步骤，写成"未能复现，原因未明"，**不要写成对已验证 Fact 的否定** |
| 回来问主会话"这里我不确定" | 主会话在解下一题。不确定就标"记录缺失" |

## 留档纪律（给主会话的提醒，也影响你）

支撑一条 `verified` Fact 的**中间产物不要删**（裁切图、dump、脚本输出、临时文件）。
踩过：主会话清理时删了 `line.png`，导致代理无法复现 OCR 结论，
只好自己重做并得出了错误的反结论。
**证据比整洁重要。** 要清就移到 `_evidence/` 子目录，不要 `rm`。
