## 4. 排查骨架：三条线

应急不是「把命令跑一遍」，是**沿三条线找证据**。任一为空，都要在报告里写明
「该线已查、未发现」—— **排除本身是结论**，也防止后来人重查。

| 线 | 问的问题 | 典型证据 |
|---|---|---|
| **A 持久化** | 重启后还能回来吗 | cron / systemd / rc.local / 计划任务 / 服务 / Run 键 / WMI / `authorized_keys` / 新增账号 |
| **B 外联** | 现在还在回连吗 | 固定间隔的心跳、非工作时段外连、新监听端口、可疑域名 |
| **C 时间线** | 从进来到现在做了什么 | 登录成功/失败、webshell 访问、进程创建、账号创建、提权、横向、打包外传 |

- **A + B 都空** → 优先怀疑「一次性攻击 / 已被对手清理」
- **C 断链** → 找日志缺口，并检查**日志是否被删**（Linux `journalctl --verify`、Windows 事件 1102）
