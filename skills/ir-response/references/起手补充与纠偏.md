### 2.0 通道：先确认「能不能命令执行」（目标是否远程，先决定这件事）

> **判据就一句：“有没有 5985？”** 有 → 全程命令行；没有 → 先用那一次 RDP 把通道打开，再转命令行。
> **截图干活是纯亏**：不可复现、贵、易误判。需要命令输出才能进证据包。

```
目标可达吗
 ├─ 5985/5986 开  → winrm probe → winrm session（★ 第一手段，Windows）
 ├─ 445 开         → SMB（wmiexec/smbexec/atexec；本机需 pip 装 impacket）
 ├─ 22 开          → OpenSSH（Windows 10+ 常装；当 Linux 用）
 └─ 只有 3389/手连 → 用那一次 RDP 把 WinRM 打开（Enable-PSRemoting + 防火墙 + portproxy），立刻关掉 RDP
```

**Windows 远程作业通道手册**：[`references/winrm-远程通道.md`](references/winrm-远程通道.md)
（11 条实测坑 · 认证矩阵 · 跳板机两种穿法 · 开局 runbook · 无 WinRM 时的备选 → 这页是 Windows 排查的**总入口**）

**开跑采集前先做两件事**：

```bash
winrm selftest                      # 1 秒：区分“我这边坏”还是“目标坏”
winrm probe <host>                  # 401/405 = 活着；000 = 不通（换通道，别硬试）
```

**采集直接落证据**（自动带 host/user/时间戳头部）：

```bash
PI_WINRM_EVIDENCE_DIR=work/<pid>/evidence \
  winrm session <host> < skills/ir-response/practice/winrm-三条线采集.txt
```

## 8. 卡住时：先纠偏，再换线索

```bash
python3 skills/ir-response/scripts/loop-check.py <pid>     # 打转检测 + 纠偏提示（exit 1 = 在打转）
```

它从图里读三个信号：**重复的 Fact**、**反复 claim/release 的 Step**、**被反复拒绝的投递**，
再加一个「N 分钟没有新 Fact」的停摆判定。命中就按输出的提示重写 3-6 步 todo。

人工换线索顺序（比换命令更有效）：

1. `fgs show <pid>` —— 图上已经写了「试过、不行」吗？别重试
2. **换证据源**：主机看不到 → 网络侧（流量/防火墙/NDR）；端点无日志 → 应用日志/数据库审计
3. `poc "<组件/特征词>"` 查本地 11290 条 POC；`tools/knowledge/INDEX.md` 查离线方法论；
   `tools/knowledge/noptrace/NOPTrace-{Linux,Windows}.md` 查手册细节（**别整读，先 grep 目录**）
4. 三条都空 → 明确写「已排查范围 + 未排查范围 + 建议」，别硬凑结论
