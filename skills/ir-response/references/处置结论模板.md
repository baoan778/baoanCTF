## 7. 处置结论（报告必需四段）

```
1) 结论        是否确认为入侵事件？依据哪几条 IOC（逐条引出）
2) 攻击链      按时间线还原：进入 → 落地 → 提权 → 横向 → 外联/外传
3) 影响面      涉事账号 / 主机 / 数据范围；未确认的边界写明"未确认"
4) 处置动作    清什么（精确到路径）、改什么、怎么验证清干净了
```

第 4 段是**唯一能落地**的部分：

| 动作 | 具体到 | 验证方式 |
|---|---|---|
| 清除 | 路径 + 哈希 + 为什么认定恶意 | 删除后**按同样命令复检**，输出进报告 |
| 阻断 | 域名/IP/端口（带出处） | `ss -antp` 复检 + 网关侧确认 |
| 加固 | 具体配置项与目标值 | 配置托管 / 复检命令 |
| 重置 | 哪些账号/密钥必须换（含"怀疑已泄露"的） | —— |

**善后不能只修当前主机。** 横向定损五个必答问题与扩面优先清单见
**[practice/post-incident-and-lateral.md](practice/post-incident-and-lateral.md)**：
是否同密码 / 同漏洞版本 / 同管理员 / 有互信（SSH key、RDP 凭据、域信任）/ 案发时段高频交互。

**交付纪律**：区分「**已确认**」与「**建议进一步排查**」，并写清哪些线没查、为什么（无镜像/无日志）。
宁可少写一条，不要编一条。
