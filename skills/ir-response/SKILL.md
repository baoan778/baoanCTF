# 应急响应

> 身份三向之一（CTF / SRC 渗透 / **应急响应**）。CTF 取证问「怎么把 flag 抠出来」，
> 应急响应问「**怎么进来的 / 还在不在 / 干了什么 / 怎么确认清干净了**」。
> 交付物是**可复现的结论 + 可执行的处置动作**，不是 flag。

## 0. 四条铁律（先立住，再动手）

1. **先保全，再分析。** 任何写操作都可能毁证。镜像/挂载一律**只读**（`mount -o ro,noatime`），
   拿到的原始物**先算哈希**（`sha256sum`）并写进报告 —— 后面所有结论都挂在这份原始物上。
2. **只读不改。** 不在目标机上装工具、不 kill 进程、不删可疑文件、不改配置。要动就**先镜像**。
   证据可能消失时，宁可先**暂停**（Linux `kill -SIGSTOP` / Windows `pssuspend`）也不要直接杀：
   ```bash
   kill -SIGSTOP <pid>   # 冻结：进程还在、证据还在、影响面可控
   kill -SIGCONT <pid>   # 验证完再决定放行还是处置
   ```
3. **结论分三级**（与 CTF 同一条纪律）：**原始输出** → **推断** → **已验证**。
   每条 IOC / 每个处置建议都必须能指出「依据哪条命令的哪段输出」。**没有出处的"疑似"不算发现。**
4. **HITL 闸门（人工确认），新增但同样硬。** 满足任一条件**必须先问人**：
   隔离主机 / 封禁账号 / 下线服务；删除文件 / 重启 / 恢复系统命令；大范围封禁或猎杀。
   询问必须带齐五项：**动作、影响面、可回滚方式、预期收益、替代方案**。
   > 这条对应 `AGENTS.md` 的授权边界（不碰判定源、不删文件、不改配置、不停服务）——
   > 「只读」是默认姿态，破例要有人的签字。

> 第五门（人）：确认「事件成立」和「清干净了」这两个判断属于**人看过证据后**下的结论，
> 不要拿自己的推断当最终交付。

### 2.1 四问（写进 `work/<pid>/scope.md`）

| 问题 | 为什么关键 |
|---|---|
| 涉事主机 / 时段 / 数据边界 | 决定取证范围，避免无限深挖 |
| 谁报的、报什么现象 | 「CPU 100%」和「被通报外联 IP」是两条完全不同的线 |
| **已经做过什么处置** | 最常见的坑：管理员已经 kill/删文件/重启 —— 现场早不是案发现场 |
| 有无保留镜像 / 日志 | 没有就**先抢救**（时间敏感的易失证据） |

```bash
fgs init <pid> --kind pentest --goal "还原入侵链并给出处置结论"
fgs hint <pid> "涉事主机/时段/边界"
fgs hint <pid> "已做过的处置：…"          # 这条比什么都重要
```

### 2.2 事件分流（**先归类，再动手**）

归不进任何一类 → 先按 `triage`（证据固定 + 范围界定），**别急着处置**。

| 类型 | 最小验证入口 | 详见 |
|---|---|---|
| 挖矿 / 木马 / 远控 | 高 CPU/内存的 PID → 命令行 → 外联目标 | [event-playbook.md](by-event/index.md) §2 |
| 勒索 | 加密后缀、勒索信、加密时间窗、加密器 | §3 |
| 暴力破解 / 账号被盗 | 登录日志（4624/4625/4672、auth.log）成功与失败的**时间关系** | §4 |
| 钓鱼 | 邮件/IM 来源、附件、链接、点击用户、落地执行 | §6 |
| 隧道 / 非授权中转 | 高频短连接、固定对端、本地回环监听 | §7 |
| 数据库事件（MSSQL/MySQL/Redis/Mongo） | 登录日志、执行语句、作业/存储过程/程序集 | §8 |
| Webshell / 服务器被入侵 | access.log 异常请求 ↔ 文件落地时间 | [web-log-trace.md](by-platform/web-server.md) |
| 无落地 / 内存型驻留 | 进程、连接、内存镜像、异常脚本宿主 | §9 |
| 供应链 / 恶意软件包 | `rpm -Va` / `debsums --all`；包管理器日志 | NOPTrace 手册 |

## 3. 阶段机（FSM）：用门槛驱动，不是用清单驱动

```
detect → triage → contain → eradicate → recover → report/postmortem
```

| 阶段 | 用什么通道 / 怎么干 | **进门门槛** | **出门门槛** |
|---|---|---|---|
| `detect` | 告警接收与初筛：是不是真事件 | —— | 能说清现象与初始证据 |
| `triage` | **只读**采集（WinRM/SSH 批量跑；存证据文件），范围界定、证据固定、根因假设 | 已分流 | **最小证据集**齐了（下节） |
| `contain` | 最小影响隔离（网关/ACL/EDR 优先） | 最小证据集齐 | 隔离动作已走 HITL 并记录 |
| `eradicate` | **先备份再改**（`Copy-Item <f> <f>.bak.<ts>`）→ 最小改动 → **改后立即复验** | **可复现的根因证据（VBR）** | 关键 IOC 与持久化已清除并**复检** |
| `recover` | 恢复业务、验证无残留 | 清除已验证 | 监测一段时间无复发 |
| `report` | 交付报告与改进项（命令+输出+时间戳都在证据目录里） | —— | 报告四段齐（见 §7） |

**跨阶段纪律（Windows 远程作业）**：

- `triage` **只跑只读命令**（采集模板就是为它写的）；写操作一律留在 `eradicate` 且带备份
- 批量动作**先在一台试**：`winrm run <一台>` → 确认无误 → 再 `session` 铺开
- 任一命令挂住整批怎么办：工具自带 `PI_WINRM_TIMEOUT`（默认 240s）硬超时；重活单独跑并限时限范围
- 修复模板：**[practice/winrm-修复模板.txt](practice/winrm-修复模板.txt)**（备份→改→复验三步）

**最容易跳错的地方**：证据没固定就 contain、根因没坐实就 eradicate。
阶段名**写进 Fact 正文当语义标签**即可，不建第五种节点类型。

### 最小证据集（进 `contain` 前必须有）

- 告警原文（截图 / 原始 JSON）
- Web 访问日志片段（时间、源 IP、路径、UA、状态码）
- **主机三件套**：进程+命令行 / 网络连接 / 持久化点
- 关键文件：可疑二进制或脚本的**只读拷贝 + 哈希**
- 必要时：内存镜像、磁盘快照（**优先快照，而不是就地修复**）

命名与保管规范见 **[practice/evidence-and-custody.md](practice/evidence-and-custody.md)**。
