# 视觉 → 语义：把一张图变成可检索线索（OSINT 最弱项的正解）

> **为什么单独写这篇**：`docs/能力边界-实测.md` 记着 OSINT **1/3（33%，全表最弱）**，两次失败的归因是
> 「**图像→语义这一步靠猜**」（猜了 210+ 个建筑名全灭）和「扫描 176 万点没有可命名地标」。
> 2026-10-10 盲测证明**看图能力是好的**（随机文字/形状/颜色 3/3 全中）—— 所以缺的不是眼睛，是
> **把眼睛看到的东西翻译成"可检索语义"的稳定流水线**。这篇就是那条流水线。

## 0. 铁律

- **不要直接猜地名/建筑名**（这就是 210 次全灭的原因）。先产出**结构化语义清单**，再让清单去撞检索。
- **每条线索标置信度**（高/中/低）与**为什么**（我看到了什么）。低置信度线索只用来排序，不用来下结论。
- **多假设并存**：给出 2~3 个候选区域/城市，各自说明支持与反对的线索（不要收敛到一个）。
- 语义清单里的每条都要能**指向图里的具体位置**（"左上角招牌"、"右侧车牌"）。

## 1. 四步流水线（每条都留证据）

| 步 | 做什么 | 命令/手法 | 产出 |
|---|---|---|---|
| ① 元数据 | EXIF/GPS/机型/时间/软件 | `exiftool -a -G1 img.jpg`；无 EXIF 也要看缩略图/编辑痕迹 | 拍摄时间、机型、可能的地点 |
| ② 文字 | OCR（**中英都要**，招牌/路牌/车牌/菜单） | `tesseract img.jpg - -l chi_sim+eng`；视觉再读一遍（OCR 常漏竖排/艺术字） | 逐字文本 + 语言/字体 |
| ③ **语义清单** | **视觉结构化输出**（见 §2 模板） | `read img.jpg`（视觉）+ 必要时 `ffmpeg` 切图放大局部 | 一张表：线索｜位置｜置信度 |
| ④ 转检索式 | 把线索变关键词/图搜 | 见 §3 | 候选地点/机构 + 支持证据 |

## 2. 语义清单模板（照这个填，别自由发挥）

```
【拍摄环境】室内/街景/野外/航拍 · 白天/夜景（灯型）· 天气（阴影硬度）· 季节（植被/衣着）
【建筑】风格（现代玻璃幕墙/砖木/骑楼/苏式/仿古）· 层数 · 特征构件（塔/穹顶/钟楼/连廊/雨棚）· 外立面材质
【招牌文字】逐字抄（含拼音/英文/繁体）· 字体风格 · **Logo 形态**（圆形/盾形/配色）· 连锁品牌特征
【交通】车道线颜色与画法 · 行驶方向 · 车牌颜色/格式（新能源绿牌/蓝牌/黄牌/外文）· 车型（出租车顶灯/公交涂装）
【路侧设施】路灯样式 · 护栏 · 斑马线 · 消防栓 · 邮筒 · 垃圾桶 · 变电箱（各国差异大，**分国家极准**）
【植被】树种/修剪方式/行道树间距 · 花坛样式
【人物】衣着风格 · 校服/工装 · 语言（招牌双语文种）· 人数密度
【器材痕迹】手机水印 · 相机暗角 · 无人机视角 · 屏幕截图（滚动条/状态栏/输入法皮肤）
【水印/角落】时间戳 · 平台水印（抖音/小红书/微博）· 角落 logo（可直接反查发布者）
```

**最值钱的 5 类线索**（先看这几项，命中一个就能砍掉 90% 空间）：
1. **车牌/路牌格式**（国别）→ 2. **语言文字**（地区/语系，双语组合更准）→ 3. **连锁品牌与配色**（只在某国/某城有的店）→
4. **路侧设施样式**（消防栓/邮筒/电线杆——各国各地差异极大）→ 5. **地貌植被**（气候带）

## 3. 把清单变成检索

- **文字类**：招牌原文 → 搜索引擎（**原文字面 + 城市名**）；连锁店 → 官方门店列表；学校 → 校徽/校服 → 校名列表。
- **图搜类**：`imgintel` 给的反查链接（以图搜图）→ 选**裁剪到特征件**（招牌/建筑局部）再搜，比整图准。
- **地理类**：`geo` 关键要素（海岸线走向/山脊/河道/桥梁型式）+ 时区光照（太阳高度角估时段）→ 先在候选国家里找同型设施。
- **视频/多帧**：`ffmpeg -i v.mp4 -vf fps=2 f_%03d.png` 抽帧 → 逐帧同法；路牌常在某一帧最清楚（**先全帧扫一遍**，别只看首帧）。
- **音频**：`sox` 出频谱 + 环境声（鸟/方言广播/报站）→ 语言与地区。

## 4. 交叉验证（决定要不要下结论）

- 至少**两条独立线索指向同一地点**才写结论；只有一条就写"候选 + 待验证"。
- 写清**反对线索**（例如语言像 A 国但路侧设施像 B 国 → 说明可能是边境/影视布景/老照片）。
- 结论格式：`候选地点｜支持线索（逐条）｜反对线索｜置信度｜下一张要找的图/要搜的词`。

## 5. 反模式（写在这里就是别再做）

| 反模式 | 为什么错 |
|---|---|
| 直接猜地名/建筑名 200 次 | 猜中的概率≈0，且浪费预算；先出语义清单再检索 |
| 只跑 OCR 就下结论 | 招牌可能是连锁店（同品牌全国都有），不构成唯一性 |
| 只看整图搜图 | 全图含天空/路面等噪声；**裁剪特征件**（招牌/车牌/建筑尖顶）准得多 |
| 用天气/季节当唯一依据 | 相似气候带太多；它只用于**排序** |
| 忽略角落水印 | 平台水印常常直接给出账号 → 反查发布者比地理定位快得多 |

## 6. 我在实战里怎么调这条流水线

```
① 先 `pcapmap`… 不适用；OSINT 开局：
② imgintel <图>            # 元数据 + OCR + 反查链接（已有的入口）
③ read <图>                # 视觉：按 §2 模板输出语义清单（**这一步是新增的关键**）
④ 把清单里"最值钱 5 类"逐条做检索（§3）
⑤ 至少两条独立线索交叉后才写结论（§4）
```
