## 0. 先读这一节：本机降级了什么（诚实边界）

原文核心判据是「**双经典引擎零检出**」：tesseract 与 RapidOCR 各跑一遍，都零命中才算幻觉。
**本机做不到**，实测：

| 项 | 本机实测 | 影响 |
|---|---|---|
| tesseract | ✅ 5.3.4（容器内 `/usr/bin/tesseract`，语言仅 `eng` + `osd`） | 唯一可用的经典引擎 |
| RapidOCR / easyocr / paddleocr / cnocr | ❌ 全部 `ModuleNotFoundError` | **没有第二引擎** |
| pip 装引擎 | ❌ PEP 668 管控（`externally-managed-environment`） | 不能临时补 |
| PIL / numpy / OpenCV | ❌ 容器内全无 | 原协议的「高通滤波 ASCII 渲染」做不了 |
| ffmpeg | ✅ 有 | ASR 相关可做一半 |

**→ 替代方案：同一引擎的多配置复现（4 种 PSM）。**

- **能抓到的**：LLM 读出的串在经典引擎**任何配置**下都不存在 → 强幻觉信号。
- **抓不到的**：两个引擎都会漏的**低对比度真文字**。这类必须靠像素终裁兜底，
  而本机没有 PIL/numpy，只能退到「引擎置信度旁证」。
- **结论里必须写明「非双引擎」**——`percept.py` 的通过文案会自动带上这句，
  防止后人误以为我们做了原协议级别的验证。

## 1. 适用场景

任何要把 **vision-LLM 的 OCR 输出**或 **ASR 转写**当作分析结论依据的时刻。

vision-LLM 会产生「**场景级合理文本幻觉**」：从整图场景先验编造出看似合理、
可自洽复现、反相稳定的内容。**一致性不能证明真实** —— 同一模型问三次给同一个答案，
恰恰是幻觉的典型形态（它每次都从同一套先验出发）。

---

## 2. 幻觉签名（满足任一即需验证，三条齐 = 判定幻觉）

1. **经典引擎零检出** —— 本机口径：`tesseract` 的 4 种 PSM（3/6/11/7）全部读不出该串。
   真实文字至少被一种配置部分命中。
2. **裁剪失效** —— 把画面任意象限/瓦片裁出（含 2-3x 放大）后 LLM 读不出，只有完整原图能读出。
   真实文本总在某个裁剪里可见；幻觉依赖整图场景上下文。
   （本机无 PIL，裁剪需借 `ffmpeg -vf crop=...` 或 `tesseract` 的 `--psm 10` 局部读。）
3. **位置追问矛盾** —— 追问"内容在画面什么位置"，答案与像素级渲染不符，或多次询问位置漂移。

## 3. 强制流程（未完成不得写进结论）

```bash
# ① LLM 给出文本 T
# ② 跑多配置复现（这一条是本机的"双引擎"替代）
py board/percept.py verify --img shot.png --claim "T"

# ③ 退出码 0（完整命中）→ 通过，可采用，结论里标注验证方式
#    退出码 3（零命中）→ 高度可疑，进 ④
# ④ 像素终裁辅助（本机退化为置信度旁证）
py board/percept.py pixels --img shot.png --region x,y,w,h
# ⑤ 仍找不到字形 → 判幻觉，弃用 T，并归档（结论 + 证据链）
```

**关键纪律：判幻觉后必须归档**，防止后续轮次重复采信同一条幻觉。

## 4. 像素终裁法（判定"文本变化"的真伪）

声称「文本 A 变成文本 B」时，对前后两帧做逐像素差异图：

- **真实变化** → 差异图中出现**字形形状**的局部差异簇（数字/字母笔画轮廓）
- **无字形差异簇**（仅全局亮度渐变、边缘移动、噪声）→ 所谓"变化"是对比度跨越
  LLM 判读阈值产生的**伪翻转**
- **辅助判据**：低对比度过渡期的 LLM 读数若在同一位上随机摇摆（如 `3`/`8` 交替），
  即为伪翻转特征

> 本机差异图工具：`ffmpeg -i a.png -i b.png -filter_complex "blend=all_mode=difference" diff.png`

## 5. ASR 专项规则

1. **模型选择**：结论性转写必须用本地最强模型（如 `large-v3`）；`base`/`small` 仅作预筛，
   **其输出不得作为依据**。
2. **空输出 ≠ 漏检**：大模型返回空/无段落，而小模型有"输出"时，**优先怀疑小模型幻觉**。
   已知名单：对音乐/纯伴奏，小模型常幻觉 "Thanks for watching"、字幕样式文本、百分比播报。
3. **音乐判别**：转写失败时先做频谱分析 —— 连续谐波结构（基频 + 泛音列随时间平滑移动）
   = 音乐/非语音；语音则呈共振峰结构与音节节奏。
   （`ffmpeg -i x.wav -lavfi showspectrumpic=s=1024x512 spec.png`）
4. **倒放检验**：可疑"语音"反转后重转写（经典隐写手法）；两向皆空 + 音乐频谱 → 关闭音频方向。

## 6. 成功/失败判据

| 情形 | 判定 | 动作 |
|---|---|---|
| 多配置 ≥1 完整命中 | **通过** | 可采用，结论标注「tesseract 多配置复现（非双引擎）」 |
| 字符覆盖 ≥80% 但未完整命中 | **可疑** | 做像素终裁再定，不得直接采信 |
| 四种配置全部零命中（覆盖 <80%） | **判幻觉** | 从候选中永久移除，归档证据链 |
| 引擎置信度高且认到字形 | **强证据有字** | 可采用（旁证，仍需说明是旁证） |

**案例自测**（原文档记录）：低对比度监控视频帧上 LLM 稳定读出 7 位数字，
双引擎全图/裁剪零检出、消融失效、差异图无字形簇 → 按本协议判幻觉并关闭该线索。

## 7. 与 baoan 现有链路的关系

- **`fgs verify`**（逐字溯源 byte-exact）仍是**硬门禁**：flag 必须在真实输出里逐字出现。
  本规程管的是**更上游**的事：那段"真实输出"本身是不是模型看错了。
- **`board/flagq.py`**（只告警不拦截）管 flag **形状像不像**；本规程管**内容是不是幻觉**。
  三者分层，互不替代。
- 若 OCR 结果要落 `fgs fact-add`，**先过本规程**再 verify —— 顺序反了会把幻觉固化成 verified。
