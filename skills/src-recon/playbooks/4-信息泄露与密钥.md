# 品类 4 · 信息泄露 → 密钥 → 利用链（「更土的路」）

> **为什么独立成类**：这是**命中率最高、最不需要想象力**的一类 —— 也是 XBOW 那条
> 「**the mundane path around is far more common than the spectacular path through**」的落点。
> 拿到 key 往往直接结束战斗，比找 0day 快一个数量级。
> 来源：XBOW 1,060 次实战 · PortSwigger · 本仓库「目标硬化时的下一步」四问。

## 何时用
- 正面打不动（注入/越权都无果）
- 目标有前端 JS 包 / 移动端包 / 小程序包 / 公开仓库
- 有报错页、配置接口、备份文件

## 探测（按"便宜程度"排序，先做不要钱的）

```bash
# ① 源码泄露（0 成本，先跑）
githack https://T/.git/ ; rip-git -u https://T/.git/ -v ; dumpall https://T/
#   .svn/.hg/.bzr、.DS_Store、backup.zip、www.zip、*.bak、*.swp

# ①b 密钥扫描（⚠ 本机没有 gitleaks/trufflehog —— 用装好的 detect-secrets）
tools/venv/bin/python -m detect_secrets scan ./泄露下来的源码/     # JSON 输出，可机器判
#   小程序包另有一条：py tools/wxapkg.py scan ./src（17 类含密钥/云env/OSS直链）

# ② 前端 JS 抠接口与密钥（本机工具）
katana -u https://T -jc -kf all -d 3 -rl 5 -c 3 -silent -o urls.txt
urlfinder -d T ; jsfinder -u https://T/app.js
#   小程序包：py tools/wxapkg.py scan ./src     ← 17 类攻击面（越权路由/密钥/云env/身份证/OSS直链）

# ③ 报错页/配置接口
curl -s https://T/api/xxx | head -c 500        # 栈信息、内网 IP、框架版本
curl -s https://T/actuator/env ; curl -s https://T/swagger-ui.html ; curl -s https://T/.env

# ④ 公开仓库与历史（0 请求打目标）
#   GitHub 代码搜索（走代理）：搜索 "T.com" + password/secret/token
#   注意：仓库历史里的已删密钥仍可检出
```

## 判据（**必须验证"能用"** —— 这条最常被违反）

| 找到什么 | 判据（不到这一步不算洞） |
|---|---|
| 云厂商 AK/SK | 用它**调通一个只读 API**（列桶/列实例）→ 若还能写，只做**无害读**并标注 |
| 数据库连接串 | 能连上并**只 `SELECT 1`**（**禁止 dump 任何表**） |
| JWT 签名密钥 | 能**伪造 token 访问受保护资源** |
| 第三方 API key（地图/短信/LLM） | 调通一次最小请求 |
| **内网地址/拓扑** | 只作报告加分项，**不是独立洞** |
| 身份证号/手机号 | 核对**是否真实数据**（测试数据不算）；命中四类死规矩才收 |

**★ 一句话铁律**：**看到一个字符串不算洞，用它干成一件事才算。**

## 利用链（把单品串起来 —— 这才是 SRC 要的）

```
源码泄露（.git） → 找到测试环境地址 + 硬编码密钥
   → 测试环境鉴权更弱 → 用密钥登录 → 拿到生产凭证 → 访问生产数据
```
XBOW 的 48 步链本质就是这样：**每一步都简单，串起来不简单**。
**动作**：每找到一块，回头问「这块能让我进哪一步？」—— 而不是收工。

## 坑
- **`.git` 拿到源码 ≠ 洞**：要从源码里**找出可利用的东西**（密钥/接口/逻辑）
- **测试环境更弱**是常态：源码里的 `beta` / `test` / `dev` / `staging` 地址优先试
- **别脱库**：发现能读全表 → **立刻停手**，报告写「可读全表（**未**遍历）」+ 单条样本
- **云存储直链**：`x-oss-` / `oss-cn-` / `.aliyuncs.com` / `minio` / `bucket` → 试列目录（只列不下载）

## 证据怎么留
```bash
fgs fact-add <pid> "源码泄露找到 <什么>，用它 <干成了什么>" --confidence verified \
    --verdict accepted --severity high --proof-kind side_read --target <host>
```
**密钥类必须带**：密钥出处（文件+行）+ **用它调通的那个请求与响应**。
**绝不能**只贴一个 key 字符串当结论。
