# 品类 6 · 基础设施层（请求走私 / 缓存欺骗 / HTTP2 / HPP / 子域接管）

> **为什么独立成类**：这些**不在应用逻辑里**，而在 **CDN + 代理 + 源站** 的**解析差异**里。
> 研究界共识（2026）：**请求走私是复杂栈（CDN+WAF+源站）上 ROI 最高的 bug**。
> 缺点：**需要真实的多跳架构**才能测 —— 单机应用测不了，所以单独成册、按需查。
> 来源：PortSwigger（Kettle《Gotta cache 'em all》）· `yaklang/hack-skills` request-smuggling / http2 / web-cache-deception / subdomain-takeover。

## 何时用
- 响应头有 CDN/代理痕迹：`X-Cache` / `CF-Cache-Status` / `Age` / `Via` / `X-Served-By` / `Server: nginx`
- `Server` 与 `X-Powered-By` **不一致**（前端代理 + 后端应用服务器 = 双解析器）
- 有子域且 CNAME 指向第三方托管

## 一、HTTP 请求走私（framing 不一致）

**核心**：两跳对「请求在哪结束」理解不同 → 夹带第二个请求。

| 变体 | 谁信什么 | 探测 body |
|---|---|---|
| **CL.TE** | 前端信 `Content-Length`、后端信 chunked | `0\r\n\r\nSMUGGLED`（配 `CL: 13` + `TE: chunked`） |
| **TE.CL** | 反过来 | `8\r\nSMUGGLED\r\n0\r\n\r\n`（配 `TE: chunked` + `CL: 3`） |
| **TE.TE** | 双方都认 TE，一方被**混淆** | `Transfer-Encoding : chunked`（**冒号前空格**）· `xchunked` · 重复头 |
| **H2.CL / H2.TE** | HTTP/2 降级到 H1 时注入 CL/TE | 见下 |

**判据（三条，别只看响应码）**：
1. **时间延迟**：夹带的请求打慢端点 → 第二个请求响应**明显变慢** = 成立
2. **差分**：连发两次正常请求，第二次收到**属于第一个的响应** = 队列被污染
3. ★ **安全探测**：先只夹带一个打到**自己 dnslog** 的请求（**0 危害**），确认后再升级

**坑**：
- 经典变体**需要连接复用**才能打别人；不复用时用 **request tunnelling**（更窄，仍能绕前端鉴权）
- 浏览器侧用 **client-side desync**（不需要共享连接）
- **只讲 HTTP/1.1 的工具测不出来** —— HTTP/2 要用 Burp 的 H2 模式或 `h2spacex`

## 二、HTTP/2 专有

| 攻击 | 说明 | 工具 |
|---|---|---|
| **h2c 走私** | 明文 H2 升级（`Upgrade: h2c`）→ 前端不校验升级后的请求 → **绕过前端鉴权直达后端** | ⚠ 本机**没有** `h2csmuggler`。手工做法：发 `Upgrade: h2c` + `HTTP2-Settings` 头（curl 不能正确构造）→ 用 `tools/venv/bin/python` 裸 socket 或 Burp H2 模式；**需真环境才能验，未实操** |
| **伪头注入** | `:path` / `:method` / `:authority` 可控时注入 CRLF 或越权路径 | Burp H2 模式 |
| **单包 H2 desync** | 能打穿部分 serverless LB（如 Cloudflare Workers） | `h2spacex`（本机已装） |

**先测**：`curl -sI --http2 https://T/ -o /dev/null -w '%{http_version}\n'` → `2` = 支持。

## 三、Web 缓存欺骗（WCD）—— 偷他人已认证数据

```
① 诱导受害者访问 /account/profile/nonexistent.css
② 源站忽略尾部 → 返回 /account/profile（含受害者私数据）
③ CDN 看到 .css → 当成静态资源缓存
④ 攻击者匿名请求同一 URL → 拿到缓存里的受害者数据
```

**路径混淆 payload（逐个试）**：
```
/account/profile/nonexistent.css     ← 经典
/account/profile.css                 ← 直接加后缀
/account/profile;.css                ← 分号（Tomcat）
/account/profile%00.css
/account/profile/..%2f.css
/account/profile?x=.css
/account/profile#.css
```

**验缓存判据（必须走到第 2 步）**：
1. 带认证请求一次 → 看 `X-Cache: hit/miss` / `Age:` / `CF-Cache-Status`
2. **不带认证再请求同一 URL** → **仍返回私数据 = 实锤**

**别搞混**：**deception**（偷一个受害者的数据，一对一）vs **poisoning**（投毒给所有人）。
URL 解析差异是主战场（CDN 与源站对 `#`、`;`、`%2f`、`..` 的解析不同）。

## 四、HTTP 参数污染（HPP）

同参数给两次，前端与后端取值不同：
```
?id=1&id=2      # PHP 取后者 · ASP 逗号连接 · Node 取数组
```
**用途**：绕 WAF 规则 · 绕参数级校验 · 污染重定向目标。

## 五、子域接管（dangling DNS）

**信号**：CNAME 指向**已释放的第三方服务**（S3 / GitHub Pages / Heroku / Vercel / Netlify / Azure / 阿里云 OSS）
+ 该服务返回 **404 + 特定指纹**（如 S3 `NoSuchBucket`）。

**流程**（⚠ 本机**没有** `subfinder`/`dnsx`/`dig`/`host`/`nslookup` —— 用下面验证过的替代）：

```bash
# ① CNAME 枚举（dnspython 在 tools/venv 里，系统 python3 没有）
tools/venv/bin/python - <<'EOF'
import dns.resolver
r = dns.resolver.Resolver(); r.nameservers=['223.5.5.5']; r.lifetime=5
for sub in open('$PI_LAB_ROOT/tools/knowledge/riftx/recommended-skills/recon-subdomain/assets/subdomains-top5k.txt'):
    h = sub.strip() + '.TARGET.com'
    try:
        print(h, '->', [str(c) for c in r.resolve(h,'CNAME')])
    except Exception: pass
EOF

# ② 直接上 subjack（它自己解析 CNAME）—— ★ 必须显式给 -c，默认 config 是 Windows 路径会失效
subjack -d TARGET.com -w $PI_LAB_ROOT/tools/knowledge/riftx/recommended-skills/recon-subdomain/assets/subdomains-top5k.txt \
        -c /mnt/d/AI/dsh/aigongju/subjack/src/fingerprints.json -ssl -t 10 -timeout 15 -o takeover.txt -v
```

**流程**：枚举 CNAME → 匹配指纹表（`subjack -c` 已内置）→ 在该服务注册同名资源。
**⚠ 边界**：这一步**真的占了别人的域名** —— **只在明确授权范围内做**，且用最轻的证明方式
（建资源 → 放一个标注文件 → 立刻删），**别把内容挂上去**。
**判据**：能**控制内容**或**读到凭证**才算（接管本身不算高危）。

## 坑
- **单机应用测不了前两类**（走私/缓存都需要 CDN+源站双解析器）—— 别在单机目标上白试
- **走私安全探测先行**（dnslog），别直接夹带真实请求
- **WCD 的 payload 是路径不是参数** —— 别往 query 里塞
- 子域接管**注意边界**（见上）

## 证据怎么留
```bash
fgs fact-add <pid> "<结论>" --confidence verified --verdict accepted \
    --severity high --proof-kind side_read --target <host>
```
走私类留：**时间差证据**（两次请求的耗时对比）或**差分响应**（收到别人的响应）。
缓存类留：**带认证 + 不带认证两次请求的完整响应头对比**（`X-Cache` 是关键）。
