### 卡在「不知道还能测什么」时：三条外部知识基线（按需取）

```bash
bash tools/kb_fetch.sh get howtohunt      # 每个漏洞类的测试方法论 + test case（不知道测什么时读它）
bash tools/kb_fetch.sh get bounty-reports # ★ HackerOne 公开报告 —— 真实报告 = 「什么本该被拒」的 oracle
bash tools/kb_fetch.sh get bugbounty-all  # bypasses + payloads（payload 被拦时的算子表）
```

**按需取，别预存**（全量入库是臃肿，且会过时）。三条各管一段：
**测什么**（howtohunt）→ **判据从哪来**（bounty-reports）→ **被拦了怎么办**（bugbounty-all）。

### 目标硬化时的下一步：「绕过去」优先于「穿过去」

> 依据：XBOW 1,060 次实战自述（2026）——「**the mundane path around is far more common than
the spectacular path through**」。举例：不是穿过加密，而是在 DLL 里找到遗留的签名密钥。
> 与 arXiv:2602.17622 的 Type B 失败模式对应：智能体会**过度承诺低价值分支**，
> 因为缺少「这条路要几步」的实时预估。

**正面打不动时，按顺序先问这四句（每句都是低成本高命中）：**

1. **有没有遗留的密钥/凭据？** —— 客户端包、前端 JS、公开仓库、配置接口、备份文件、
   报错页面里的调试信息。拿到 key 往往直接结束战斗。
2. **有没有「配置错误 + 一个已存在的小毛病」能串起来？** —— XBOW 的 48 步链本质就是
   盲 SSRF + GDAL 解析 + VRT 引用本地路径拼出来的，**每一步都简单**。
3. **有没有差分错误响应？** —— 同一请求改一个字节看响应差异（padding oracle、布尔盲注、
   用户名枚举都是这个形状）。**差分比 payload 值钱。**
4. **版本比对** —— 拿到确切版本号去比对该版本的**已知绕过**（不是已知 CVE，是已知的
   绕过技巧/配置错误），往往比找 0day 快。

**强制自问**：「有没有**更土**的路？」——找漂亮洞是本能，但**土路命中率更高**。

**同时防过度承诺**：一条路试到第 3 次仍无新增信息 → 记一条证伪 Fact 换攻击面。
**预估步数**：上一条路之前先问「这条大概要 3 步还是 30 步」；估不出 30 步的具体形状就先别投。

### 拿到接口清单之后：跑鉴权差分（别手搓 curl）

```bash
# 同一条接口放到不同身份下请求，确定性比对响应
python3 tools/authzdiff.py run --endpoints eps.txt \
    --profile anon=none.json --profile sessA=a.json --profile sessB=b.json --qps 1
python3 tools/authzdiff.py selftest          # 本地 mock，5/5 判据 + 4 项护栏
```

判定：`INNER_DENY` **自证未授权**（响应体自己说未登录却有数据）· `ANON_OK` 未授权 ·
`WRITE_IDOR` 写操作型越权 · `CROSS_IDENT` 水平越权 · `VERT_ESCALATE` 垂直越权 ·
`UNKNOWN` 模糊区间/5xx（**别当噪音丢，必须人工看**）· `ANON_DENIED` 已防护✓ · `NOISE`。

**profile 五档约定**（借鉴 spec-less scanner 的 principal matrix）：
`anon`（无 token）/ `invalid`（无效 token）/ `low`（普通用户）/ `high`（admin）/ `sessB`（同权第二个账号）。

### 越权测完还要测的两类（传统扫描器一律看不见，`Pattyboi101/LogicGate`）

| 类别 | 找什么 | 怎么试 |
|---|---|---|
| **LG003 状态机操纵** | `status` / `state` / `step` / `stage` / `flowId` 字段 | **跳步**：直接置终态（`cancelled`→`confirmed`）、跳过校验步骤、拿未完成订单去退 |
| **LG004 多租户泄漏** | `tenantId` / `orgId` / `corpId` / `merchantId` / `shopId` / `appId` | 换一个值看**跨租户数据**（多租户 SaaS 里这是头号洞） |

这两类的判据不是「返回 200」，而是**状态真的变了**或**真的看到别家数据**。
写类验证一律走无害证据协议（自建哨兵 / 幂等回写原值）。

### 裁决怎么落回黑板（这就是它跟「写份报告」的区别）

复审不是「问一次代理」，它的结论**直接变成图上的动作**（契约：`board/schema.md`）：

| 裁决 | 黑板动作 |
|---|---|
| `accepted` | 落 `verified` Fact，`meta{verdict:accepted, severity, proof_kind, target, repro}（`action=verify` 可选）`，再 `fgs relate --type satisfies` 指向 goal（不挂在图上会被 `fgs solved` 拒） |
| `ignored` | 同样落一条 `verified` Fact（"这条被证伪/不收"）—— 后一个人不会再重跑 |
| `deepen` | **不落 Fact**，派生 Step（带 `derived_from` 指回线索 Fact），下一轮 explore 去打穿 |

`meta.proof_kind` 是写/删/改类的**无害证据类型**：`sentinel` / `authz_diff` / `idempotent` / `side_read`；
填 `weak` 或漏填 → `fgs doctor` 会提醒「缺无害证据」。

### 通杀：`fgs swarm`（一打一片）

一条坐实的结论 + 一批同款目标 → N 条并行 Step：

```bash
fgs swarm <pid> --from f003 --targets a.edu.cn,b.edu.cn --dry-run    # 先预览
fgs swarm <pid> --from f003 --targets-file targets.txt \
    --text "在 {target} 用同一 payload 验证，各自留响应证据"
```

源必须 `verified`；每条带 `derived_from` 指回源；同文本幂等；默认上限 5（硬上限 20，超出要 `--force`）。
**每个目标各自取证**，不许拿 A 站的响应证明 B 站。

目标是多个资产时，先看 **[`references/目标优先级.md`](references/目标优先级.md)**（先打谁 + 通杀一打一片）。

### ⚠ 被打回来/被封的判据（实战高频，别猜）

「403 / filtered / 超时」**不等于**被封。三种形态处置完全不同 —— 判错一次浪费几十分钟：

| 现象 | 真因 | 处置 |
|---|---|---|
| 端口大量 `filtered` | 对端对 **SYN 扫描限速** | **降速**：`nmap -Pn -sS -p- -T1 --min-rate 80 --max-retries 5 --open`（`quiet scan`） |
| 域名 403、IP 正常 | **域名层拦截**（阿里云 ICP/CDN 规则） | **IP 直连 + `Host: 域名`** 继续；**换出口无效** |
| 全站 403/429/重置 | IP 层被限/被封 | 停手 5–15min → `quiet egress use <节点>` → 降 QPS≤0.3 再来 |

一条命令出判据：`quiet trap <IP> <域名>`。完整打法见 **[`references/对抗-别把IP打没.md`](references/对抗-别把IP打没.md)**。
