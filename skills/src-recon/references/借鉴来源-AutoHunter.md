## 一、它是什么（和我这边不是一个形状）

**一台机器 = 7×24 挖洞平台**，人只当复审员。流水线：

```
Collector(FOFA 搜集 → 探活 → 预筛 → 评分 → 归属标注)
   → Worker(1 目标 1 worker，LLM 自主侦察 + 真实工具链 nmap/nuclei/sqlmap/httpx)
   → Reviewer(极理性 AI 初审：过滤半成品/误报，或打回深挖)
   → 人工复审(调级/通过/打回/标记提交)
   → 待提交清单 / 通杀 Hunter(一打一片) / 扩大危害 Hunter(顺口子再下一层)
```

关键差异（决定了什么能抄、什么不能抄）：

| 维度 | AutoHunter | pi-lab |
|---|---|---|
| 形状 | **广度优先**：目标多、每目标中浅、流水线漏斗 | **深度优先**：目标少、单点深挖、黑板状态空间搜索（Cairn） |
| 目标 | 海量（FOFA 持续产） | 你发我打（题面 / 授权资产） |
| 决策 | 规则 + 流水线阶段 | `fgs next` 三任务 + 人在环 |
| 记忆 | 情报库（凭证/端点/指纹）+ SQLite | 黑板图（goal/step/fact/hint）+ 手法库 |
| 交付 | Web 控制台 + EduSRC 提交 JSON | TUI + WP + 交接包 |

**结论：它的"控制流"我不抄（我这边 Cairn 那套更合身），它的"领域判据与工作量"值得抄。**

## 二、采纳了什么（已落地）

| 采纳 | 落到哪 | 为什么值 |
|---|---|---|
| **收洞判定尺子**（收/不收/打回深挖三裁决、敏感信息四类死规矩、公开接口识别、未授权访问收取门槛、验证码三种辨析、后门判定、定级参考） | `skills/src-recon/references/收洞判定.md` | pi-lab 原来的 src-recon **只有工作流、没有判据**：能"验证"，但说不清"这算不算洞"。这是最贵的缺口 —— 判错=白报或被驳回 |
| **无害证据协议**（自建哨兵增改删闭环 / 未登录 401-403 对照 / 幂等回写；禁止硬删真数据；写删 PoC 不许现场复放） | 同上 | 把我 AGENTS.md 里"不删文件、不改系统配置"这条**空纪律**变成了**可操作的取证方法** —— 不是"不许验证写操作"，而是"写明你的无害闭环" |
| **目标优先级评分表**（正/负向权重 + 高价值端点 + 死目标快速放弃） | `skills/src-recon/references/目标优先级.md` | 多目标时"先打谁"有了依据；同时保留它的理念：**评分只决定顺序，不代表放弃** |
| **通杀（一打一片）** | 同上 | 一个指纹确认后批量验证同款站点 —— 在黑板里就是"一条 Fact 派生 N 条并行 Step"，正好是 Cairn 的多 intent 模型 |
| **独立复审闸门** | `skills/src-recon/references/src-reviewer.md` | 与已有的 `solved → confirm`、`publish → apply` 同构：**Worker 有确认偏误，所以判据要交给只看证据的独立视角** |

## 三、没采纳（以及为什么）

| 没采纳 | 为什么 |
|---|---|
| FOFA 搜集 / 资产测绘 | pi-lab 的目标是你给的授权资产，不需要自己"找"目标（这也是授权边界更干净的原因） |
| 容器池 / 1 target : 1 worker / 7×24 无人值守 | pi-lab 是单机 + 人在环。Cairn 那边已经定了"项目容器用目录隔离，不搞 Docker" |
| Vue 控制台 / FastAPI / SQLite | 单机单写者：文件 + 原子替换更简单也更好审查；看板要的话从 `graph.json` 生成静态 HTML 就够 |
| EduSRC 归属离线反查 + 提交 JSON | 强绑定某一个平台的口径；pi-lab 的 flag/提交由**人**过 `fgs confirm` |
| LLM 工具调用兼容层（无 tool-calling 的模型用提示词模拟） | pi 自带工具调用，不需要这层 shim |
| 情报库（凭证/端点/指纹全局复用） | **有价值但暂缓**：pi-lab 已有 Fact `meta`（`phase/action/verdict/tool/target/ioc`）+ `_evidence/`，跨项目抽取可以照 `board/retrospect.py` 的"候选→人审→合并"模式做，属于独立工程，不适合搭车 |

## 四、它教会我的一条设计原则

> **判据要能被独立复核，且默认姿态是"拦下"。**
> AutoHunter 的 Reviewer 有一票"打回深挖"（`deepen`）—— 既不放过半成品，也不丢掉真线索。
> 这和 pi-lab 手法库闸门的 fail-closed 是同一个东西：
> **漏判的代价不可逆（数据/结论变脏），误拦的代价只是多问一句。**
