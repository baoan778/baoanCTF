# 微信小程序渗透 —— 从「一张小程序码」到可提交的洞

> 前置：本仓库通用纪律（`skills/src-recon/SKILL.md` 的收洞判定 / 无害证据协议 / 复审）全部适用，
> 本文只写小程序**特有**的部分。工具入口：`tools/wxapkg.py`（本机自研，见文末）。

---

## 0. 先回答两个前置问题

### Q1：小程序码（菊花码）能"控制"或解出明文吗？

**不能直接解，也不需要解。** 微信小程序码是**私有码制**（放射状/菊花状，腾讯公开的设计文里写明
3 主定位点 + 1 辅助定位点 + 圆形信息编码区），**标准二维码解码器（zbar / cv2.QRCodeDetector）解不出明文**。
本机已实测：`zbar` + `opencv` 双解码器对菊花码返回空。

但**目标从来不是「码里写了什么」，而是「appid + page path」** —— 这两样有 4 条不需要破码制的路：

| 路线 | 做法 | 拿到的 | 评价 |
|---|---|---|---|
| **A. 开发者工具编译** ★ | 微信开发者工具 → 工具栏「自定义编译条件」→「**通过二维码编译**」→ 选这张码图（需 devtools 1.02.1803130+） | `appid` + 完整 `path` + `query` | **最快最准**，官方功能，等于给了你一个指定页面入口 |
| **B. PC 微信本地目录** ★ | 用微信扫这张码打开小程序 → 看 `%USERPROFILE%\Documents\WeChat Files\Applet\` <br>（Mac：`~/Library/Containers/com.tencent.xinWeChat/Data/Documents/.../Applet/`） | 目录名 = `wx<APPID>`，里面就有 `.wxapkg` | **源码直接到手**，最常用 |
| C. 明文 scheme 检索 | 码出现的页面/文章/接口返回里找 `weixin://dl/business/?appid=xxx&path=xxx&query=xxx` | appid + path | 运气活，但零成本 |
| D. 问人 | 按 `prompts/human-hint.md` 找人要一句「这是哪个小程序」 | appid | **"已知的未知"，猜 >30 次不中就停手** |

**注意区分两种码**（决定 C 路可行性和抓包对象）：

- **接口 C `wxacode.createQRCode`** → 返回**标准二维码**，`wxapkg.py qr` 能直接解出明文 payload
- **接口 A/B `getwxacode` / `getwxacodeunlimit`** → 返回**菊花码**，只能走 A/B 路
- **明文 URL Scheme** → `weixin://dl/business/?appid=*APPID*&path=*PATH*&query=*QUERY*&env_version=*`，
  需要 MP 后台「明文 Scheme 拉起此小程序」声明；**这条路拿 path 最干净**（query ≤512 字符，`url_encode`）

### Q2：源码从哪来（四选一）

1. **PC 微信本地缓存**（上面 B 路）：`Applet\wx<APPID>\<数字>.wxapkg` —— **注意 PC 版外层加了密**（`V1MMWX` 头）
2. **抓包下载**：Charles/Proxifier 抓微信小程序的包下载（微信客户端首次打开会拉 `*.wxapkg`，体积最大的那个响应基本就是主包）
3. **安卓侧**：`/data/data/com.tencent.mm/MicroMsg/<user>/appbrand/pkg/*.wxapkg`（需 root；一般**不加密**，直接是 `0xBE` 明文）
4. **云开发型小程序**：可能整包都在云函数/云库里，先反编译拿 `env` 再去打云 API

## 1. 解包三件事（本机一条命令链）

```bash
# ① PC 微信的包是加密的，先用 appid 解密（appid = Applet 目录名）
tools/venv/bin/python tools/wxapkg.py decrypt __APP__.wxapkg --appid wx0123456789abcdef
#    原理：AES-256-CBC(PBKDF2(appid,"saltiest",1000,32)) 前 1024B + 其余逐字节 XOR(appid[-2])
#    校验：解出来必须能 parse 成合法 wxapkg 才算成功（不做这种校验的解密工具会静默出错）

# ② 解容器
tools/venv/bin/python tools/wxapkg.py unpack app.wxapkg -o ./src

# ③ 猎攻击面（★ 这一步决定你后面打什么）
tools/venv/bin/python tools/wxapkg.py scan ./src
```

**`scan` 直接吐 17 类东西**，其中高价值的几类：
`越权路由`（`xxxByUserId/ByUsername/ByPhone`）、`管理路由`、`支付金额`（`total_fee/price`）、
`云开发env`、`JWT`、`云厂商AK`、`OSS 直链`、`身份证号`。

**反编译细节**（栈编译过的 WXML 需要额外工具，优先级低）：
- 主逻辑在 `app-service.js` / 分包在 `chunk_0.appservice.js` / 配置在 `app.json`、`project.config.json`、`ext.json`
- 后者里直接有 **appid**；`ext.json` 里有第三方平台的 extAppid（多商户场景的越权金矿）
- 要 WXML/WXSS 还原成可读源码再上 `wxappUnpacker` / `unveilr`（本机没装，需要时再拉）

## 2. 抓包（绝大多数洞都从这来）

微信对代理的处理比浏览器麻烦，可用的三条路：

| 方式 | 配置 | 适用 |
|---|---|---|
| **Proxifier + Burp** | Proxifier 加规则把 `WeChat.exe` 进程流量转到 Burp(8080)；Burp 导入并信任证书 | PC 微信，最稳 |
| **Fiddler → Burp 上游** | Fiddler 导根证书到「受信任的根证书颁发机构」→ act as system proxy，再转发到 Burp | Proxifier 抓不到时兜底 |
| **mitmproxy** | 安卓侧代理 + 系统证书（或改包） | 手机测试 |

**踩坑**：
- 抓不到 → 先确认 Burp 能抓到普通网页流量（证明证书链通了），再查 Proxifier 进程规则大小写
- 小程序**未必走 HTTP**：`wx.request` 是 HTTP，但**云开发调用（`cloud.callFunction`）不走 HTTP**，
  走的是微信私有长连接 → **抓不到**，只能靠反编译源码读参数，然后**直接打云 API**
- 开启了 `checkSignature`/`checkSession` 的接口，重放会在鉴权处挂掉 → 要连着 session 一起重放

**速率**：接口猜参/越权遍历一律 `quiet req <URL> --qps 1`（每 1~3 秒 1 个），
**不要** ffuf 大字典直怼业务接口——那是把 IP 打没的最快方式。判据见 `对抗-别把IP打没.md`。

## 3. 哪里好挖（按实测收益率排序）

> 微信官方自己的《常见风险及处理建议》把**接口鉴权（未授权/越权）**排在第一类 —— 这是整个生态的
> 头号问题，也是小程序挖洞的**第一现场**。源码能拿到 → 接口清单能拿到 → 鉴权对比能自动化。

| 排名 | 攻击面 | 为什么好挖 | 怎么验证 |
|---|---|---|---|
| **1** | **未授权访问 / 水平越权** | 小程序接口普遍只验「登录没登录」，不验「这条数据是不是你的」。路由名直接暴露意图 | 拿**两个身份**A/B：A 的 token 请求 B 的资源；或**不带 token** 直接请求 → 401/403 对照 |
| **2** | **垂直越权** | 前端按钮灰掉 ≠ 后端鉴权。管理接口常只靠前端隐藏 | 普通用户 token 直打管理路由；观察是否 200 + 数据落库 |
| **3** | **支付 / 金额篡改** | 客户端传 `total_fee`/`price`/`quantity`，服务端不校验 | **只验证到「订单金额被服务端接受」为止，不完成支付**；无害证据优先 |
| **4** | **前端响应篡改绕过登录** | 改响应 `code:0`、`false→true` 就进去了（实战高频） | 抓登录响应改字段 → 看是否进入工作台。**注意：这是弱证据**，要证明「能拿到真实数据」才算洞 |
| **5** | **云开发配置错误** | 云数据库集合权限设为「所有用户可读写」= 公开可写；云函数未鉴权 = 任意调用 | 用反编译拿到的 `env` 直接调 `cloud.database` 接口；**读**优先，**写**走哨兵 |
| **6** | **硬编码密钥** | `appSecret` / 云厂商 AK / 地图 AK 直接写在 JS 里 | ★ **必须验证「能用」**：AK 能调通 API 才算，只看到一个字符串不算洞 |
| **7** | **敏感信息泄露** | 注意判据：只有**身份证照片 / 人脸照 / 身份证号 / 密码哈希**四类算死规矩 | `scan` 的 `身份证` 命中要**核对是否真实数据**（测试数据不算） |
| **8** | **任意文件上传/下载** | `wx.uploadFile` / 下载接口路径参数 | 上传走**无害文件**（txt），下载走**自己上传的**文件 |
| 9 | SQL 注入 / 命令注入 | 比 Web 少（大量走 ORM），但 JSON 参数里 `orderBy`/`sortField` 是高发点 | `orderBy` 注入优先手试，sqlmap 对 JSON 支持差 |

### 3.1 越权路由的命名规律（最实用的单一技巧）

反编译后**全局搜这个正则**，命中率极高：

```
\w+[Bb]y(UserId|Uid|Id|Phone|Username|Name|Mobile|No|Code|Openid|Account)
```

实战里这类接口经常**完全没有鉴权**：`user/getUserInfoByUsername` 传个 `username` 就把
管理员的详细信息（含密码哈希）吐出来了；拿到哈希形状后注意登录接口是不是同一套
（`loginByUsernameAndPassword` 若是 MD5 当密码用，哈希直接当密码提交就能登录）。

`tools/wxapkg.py scan` 已经把这条内置成 `越权路由` 类。

### 3.2 挖洞顺序（固定，别跳）

```
解包 → scan 出接口清单
  → 按「越权路由 / 管理路由 / delete 类」排序
  → 无 token 直打一遍（未授权）          ← 0 成本，先跑一遍
  → 双身份 A/B 对照打一遍（水平越权）
  → 低权 token 打管理路由（垂直越权）
  → 支付/金额类只读到「被接受」为止
  → 复现 → 无害证据 → 独立复审（src-reviewer.md）→ 落 Fact
```

## 4. 收洞门槛（小程序特有的坑）

- **「能进后台」不等于洞**：改响应包进去但只能看到自己的数据 → `ignored`。必须拿到**别人的**数据或**管理能力**
- **公开接口识别**：未登录首页就在调、返回公开展示信息的接口 —— 既不是泄露也不是未授权（`收洞判定.md`）
- **敏感信息四类死规矩**：只认 身份证照片 / 人脸照 / 身份证号 / 密码哈希
- **写/删/改类必走无害证据**：自建哨兵增改删闭环、未登录 401/403 对照、幂等回写原值；
  **禁止硬删真数据**，**写删 PoC 不许现场复放**
- **`wx.login` 的 code 是一次性的**：重放会失败，别拿这个当「漏洞」
- **前端加密 ≠ 后端安全**：`sign`/`encrypt` 的 JS 就在包里，能复现签名；但**只有能造成危害才算洞**
