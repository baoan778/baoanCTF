# 对抗实战：别把 IP 打没（限速 / 403 / 出口）

> **来源**：京津冀蒙长城杯（高校组一等奖）赛后分享的渗透场景一/二实录 + 本机实测。
> 工具：`quiet`（低速扫描 / 封禁判据 / 出口切换 / 证据留痕）。判据优先于技巧 —— 先把"像被封"和"真被封"分开。

---

## 0. 一句话铁律

**"403 / filtered / 超时" 不等于"你被封了"。** 三种形态的处置完全不同，判错一次就浪费几十分钟：

| 形态 | 现象 | 真实原因 | 正确处置 | 错误处置 |
|---|---|---|---|---|
| ① **端口全 filtered** | 扫出来一堆 `filtered`，几乎没有 open | 对端对 **SYN 扫描限速**（丢包），不是端口关着 | **降速重扫**（见 §1） | 换出口/放弃目标 ← 全错 |
| ② **域名 403、IP 正常** | 带 `.com`/`.cn` 的请求 403；用 IP 访问正常 | **域名层拦截**（阿里云 ICP / CDN / WAF 按域名规则） | **用 IP 直连 + `Host: 域名` 头**继续 | 换出口 ← 白折腾，拦的是域名 |
| ③ **全站 403/429/连接重置** | IP、域名、换 UA 都一样被拦 | **IP 层被限/被封** | 停手冷却 → 换出口 → 降 QPS 再来 | 继续硬打 ← 越打越黑 |

## 1. 形态①：端口扫描被限速（原文实测）

> 原文：「这台机器对 SYN 扫描做了限速，常规高速扫描会得到**大量误报的 filtered 结果**。必须用低速扫描才能发现真实端口」

```bash
# 实测有效（全端口、低速、可复现）；没 root 时换 -sT
nmap -Pn -sS -p- -T1 --min-rate 80 --max-retries 5 --open <IP>

# 或直接用本机工具（内置同参数 + filtered 提醒）
quiet scan <IP>            # 默认只扫常见 25 个端口，快
quiet scan <IP> -p -       # 全端口（慢，十几分钟 —— 这就是限速的代价）
```

判据：

- `filtered` 占比高 → **对端在限速丢包**，不是端口关；继续 `-T1`，必要时加 `--scan-delay 1s`
- `-T4/-T5` 或 `--min-rate 5000+` 在防守方有速率策略时**会主动暴露你**（而且拿到的结果还是假的）
- 一旦出现「大规模 filtered」就**别再加并发**：加并发只会更黑

### 1.7 主动 vs 被动：**被动收集是最简单的"绕过 WAF"**

> 原文（信息收集被拦的成因四类）：
> ① **速度过快**「扫描工具发包的流量或速度太快，然后被拦截」；
> ② **指纹被识别**「扫描工具的指纹被识别，然后被拦截」；
> ③ **payload 被拦**「扫描工具的 payload 或者 POC 被拦截」；
> ④ **主动扫描 vs 被动扫描**——「WAF 绕过主要集中在**信息收集、漏洞发现、漏洞利用、权限控制**四个阶段」，
> 而**被动收集（走测绘平台，不对目标发请求）是最简单的绕过方式**。

| 做法 | 例子 | 什么时候用 |
|---|---|---|
| **被动优先**（0 请求打目标） | FOFA / Quake / Shodan / ZoomEye / 0.zone 查资产、证书透明日志、Wayback、`gau`、GitHub 泄露 | **开局就该先做**（本机 `enscan` 也是这条路） |
| 主动但低噪声 | `quiet req --qps 0.3` 单请求探测、逐路径手试 | 确需验证时 |
| 主动且高噪声 | `nmap -T4`、目录爆破大字典、`nuclei -t all` | **只在确认没有速率策略时**，且必限速 |

**指纹类封禁的对策**：换 UA / 改扫描器默认特征（`--random-agent`、`nuclei` 的 `-H`）、别用默认 Xray/SQLMap 特征；
`payload 被拦` 则回到 `收洞判定`：**能过 WAF 的 payload 才算验证成功**。

## 2. 形态②：域名 403、IP 正常（原文实测，最容易被误判成"封 IP"）

> 原文：「另一个坑是**阿里云 ICP 拦截**。所有带 `.com` 或 `.cn` 的域名都会返回 403，导致 **vhost 爆破完全失效，只能用 IP 访问**」

这条的推论：

- 拦的是 **HTTP 请求里的域名（Host / SNI）**，跟你的出口 IP 无关 → **换出口无效**
- vhost 爆破在这类环境里直接失效（所有域名都 403）→ 改从 **IP:端口** 侧和**页面内容/证书/报错**侧收集
- 用 IP 直连时记得**补 `Host` 头**（有些应用/容器路由依赖 Host）

```bash
# 一条命令把"域名层拦截"和"IP 被封"分开（本机工具，已实测）
quiet trap <IP> <域名> [--port 8080]

# 输出三行对比：
#   A 域名直访          status=403
#   B IP 直连(Host=IP)  status=403
#   C IP 直连(Host=域名) status=200   ← 说明是域名规则命中，用 C 的方式继续
```

判定逻辑（工具里就是这套）：

| A(域名) | B(IP+Host=IP) | C(IP+Host=域名) | 结论 |
|---|---|---|---|
| 403/429 | 正常 | 正常 | **域名层拦截** → 用 C 继续，别换出口 |
| 403/429 | 403/429 | 403/429 | **IP 层被拦（真被封）** → 停手冷却 + 换出口 |
| 正常 | 正常 | 正常 | 没拦截；保持 `quiet req --qps 1` |

## 3. 形态③：真被限/封 → 出口与节奏

### 3.1 先降节奏（最便宜的止血）

```bash
quiet req <URL> --times 20 --qps 0.3      # 每 3 秒一个请求；429/5xx 自动指数退避
quiet probe <URL>                         # 判"是不是已经进黑名单"：看状态码/重置/超时
```

- **抖动**：等间隔（正好 1.000s）比随机间隔更容易被识别；`quiet req` 自带 ±30% 抖动
- **换 UA/加 Referer**：只对"按指纹拦"的环境有用；对"按 IP 拦"无效
- 一旦全站 429 → **先停手 5–15 分钟**，别继续（继续只会把封禁时间越拉越长）

### 3.2 换出口（有 Clash 就行）

```bash
quiet ip                        # 当前出口 IP + Clash 当前选中节点
quiet egress ls                 # 列出 selector 组与可选节点
quiet egress use <节点名/关键字>  # 切节点 → 自动回报新出口 IP
# 非默认端口：CLASH_API=http://127.0.0.1:9097 CLASH_SECRET=xxx quiet egress ls
```

- 出口池够大时，**按目标分片**：同一目标固定一个出口（别在同一目标上频繁跳，反而像攻击）
- 换出口后**先 `quiet probe` 再继续**，别直接上扫描器
- 没有 Clash 时：自有代理（`QUIET_PROXY=http://ip:port`）、云主机跳板、或手机热点（最土但有效）

### 3.3 换思路：不一定要"更猛地打"

- **先被动后主动**：`gau`/Wayback、证书透明日志、页面源码/注释/sourcemap（长城杯场景二就是 `.map` 泄露直接给密钥与路由）
- **从已控面横向**：一次拿到的容器/主机往往能出网或能读到下一跳凭据（原文场景二整条链都是"上一步容器里找到下一步凭据"）
- **打点优于扫面**：单请求探测（`quiet req --show`）比批量扫描更不容易触发风控

## 4. 一条被低估的实战判断（原文的"一血"教训）

> 原文：「环境仅允许白名单入网，但我们**意外发现一个容器可以任意出网**。人会立刻意识到其价值，并将信息同步给其他 Agent，最终借此获取较新 CVE 的 EXP，**提前其他队伍至少四十分钟拿下一血**」
> 紧接着作者反思：「现在的主控 Agent……对『**一个局部信息到底意味着什么**』这件事，判断能力还是有所欠缺。」

落到我们的纪律里就是两条：

1. **"异常即情报"**：任何"本不该通却通了 / 本不该有却有了"（出网、挂载、凭据、debug 接口）都要**立刻当高价值事实落进黑板**，并派生出下一步 Step；
2. **别只把异常当噪音**：AI 常见的失败模式是"看到了、记了一句、继续按原计划走"。这条写进 `fgs` 的 reason 纪律里（见 AGENTS.md §六）。

## 4.5 两条来自赛场实测的纪律（被别的队伍/对手利用过的教训）

### 4.5.1 收工前清掉**你自己**留下的利用痕迹

> 原文案例（TCH 第二届）：**「第一天第一名没有清理渗透痕迹，导致后续队伍'前人栽树，后人乘凉'快速反超——AI 不会主动考虑行为后果。」**

- 你在目标上留下的东西：**你上传的 webshell / 自建账号 / 临时计划任务 / 调试后门 / 上传的利用脚本** → 收工前清掉（这是清理**自己的**痕迹，不是抹掉目标的日志）
- **红线别越**：不动目标的日志/审计/证据（那是别人的取证资料，也是你"可复现"的依据）；
- 授权 SRC 场景相反：**保留自己的测试痕迹清单**（时间/命令/对象），这是复现与撤离报告的材料 —— 两种场景先分清。

### 4.5.2 弱口令/口令规则要**按人类习惯推**，别只跑字典

> 原文案例（TMC 冠军之夜）：「题目中 FTP 弱口令是 `ftp@2026`，**这种人类常做的推测，AI 推导不出来**。」

拿到任何"口令规则"线索（入职须知、命名规范、年份/生日、`服务名+@+年份`）就先**按规则生成候选**再打，别直接上大字典：

```bash
# 例：从页面线索推出口令规则后小规模生成（比跑 10 万字典更省 IP 声誉）
for y in 2026 2025 2024; do for w in ftp web vpn ssh; do echo "${w}@${y}"; done; done
```

## 5. 记录与留证

```bash
PI_QUIET_EVIDENCE_DIR=work/<pid>/evidence quiet req <URL> --times 10 --qps 0.5
# → work/<pid>/evidence/quiet-YYYYMMDD.jsonl
#   每行 {ts, action, target, status, ms, bytes, note} —— 直接进证据包/报告
```

**为什么要留**：判"形态①②③"依赖**同一目标在不同时刻/不同 Host 的响应对比**；不留原始记录，事后无法复现结论（也无法向组委会证明"我打的是授权目标、且没造成影响"）。

## 6. 一页速查

```
看到 filtered  → 降速 (nmap -T1 --min-rate 80)；别加并发
看到 403       → quiet trap <IP> <域名>：域名层？还是 IP 层？
  ├ 域名层     → IP 直连 + Host: 域名；别换出口
  └ IP 层      → 停手冷却 5–15 min → quiet egress use <节点> → quiet probe 确认 → QPS≤0.3 再来
429/重置       → 立刻降 QPS + 退避（quiet req 自动做）；持续就停手
拿到异常能力   → 当高价值 Fact 立刻落黑板 + 派生 Step（"可出网"这种就是血）
```
