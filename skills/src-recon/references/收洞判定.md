# 收洞判定（什么算漏洞、什么不算、什么时候打回深挖）

> **来源与署名**：本文件是对 [AutoHunter](https://github.com/StanleyNull/AutoHunter)（作者 StanleyNull，
> 许可 **CC BY-NC 4.0，非商业**）`app/agents/prompts.py` 里 Reviewer 判定标准与
> `app/agents/write_proof.py` 无害证据协议的**蒸馏与改写**，按 pi-lab 的语境重写，仅个人授权测试使用。
> 原文判定以 EduSRC 口径为主，企业 SRC 同样适用（尺度可放宽，死规矩与无害证法不变）。

---

## 最高铁律：只认「实际可利用 + 实锤危害」

**理论上存在 ≠ 漏洞。光泄露 ≠ 漏洞。配置不当但没打出实际危害 ≠ 漏洞。**

任何发现都要追问一句：**「然后呢？危害实锤了吗？」**
拿不出"利用这个缺陷实际造成了什么后果"的证据，就不要报，或者降级重估。

> 扫描器视角的"问题点"一大把，但甲方只为**能打出真实危害的攻击**付费。
> 宁可把一个半成品判成 `ignored`，也不要把它推到人面前浪费时间 —— 但**有价值的线索不要丢**，
> 那属于第三种裁决（见下）。

## 三种裁决（第三种是核心）

| 裁决 | 什么时候用 | 含义 |
|---|---|---|
| `accepted` | 危害有实证、证据链完整 | 可以报 |
| `ignored` | 纯垃圾 / 明确不收的类型 / 已证明打不穿 | 丢掉 |
| **`deepen`** | **线索真实、利用大概率可行，但这一轮没打穿** | **带着定向指令再挖一轮** |

`deepen` 必须同时满足三条：① 线索真实（不是臆想）；② 有明确的下一步利用路径，打穿后是中危以上；
③ 这一轮只是**没去做或没做完**（不是做了但证明打不穿）。

打回时要写清**定向指令**（具体到接口/参数/目标），例：
- 「用 JS 里的 `appSecret` 对 `/api/user/info` 做签名，越权取他人信息并贴响应」
- 「用泄露的地图 Key 实际发一次计费调用，证明可盗刷配额（贴成功响应）」

> `deepen` 不是垃圾桶：纯垃圾、明确不收的类型、已证伪的，直接 `ignored`。

## 敏感信息泄露的「死规矩」：只认四类数据

1. 身份证照片
2. 大头照 / 人脸照片
3. 身份证号码
4. 密码哈希（口令散列 / 明文口令）

**其余一律不算**：设备信息/设备 ID、商品价格、姓名、手机号、邮箱、地址、订单、校区、
管理员账号名、运行状态、各类统计与展示数据 —— 泄露这些**不能**按"敏感信息泄露"收。

## 公开接口识别（判之前先问：这接口本来就是给所有人看的吗？）

大量接口设计上就是公开的：未登录首页就在正常调它、返回的是面向公众的展示信息
（公告/介绍/列表/预约状态）、官网前端公开使用、没有任何越权语义。

→ 判为公开接口 = **既不是信息泄露，也不是未授权访问**，直接 `ignored`。

## 敏感信息泄露 ≠ 越权/未授权访问（两个独立类别）

- **敏感信息泄露**：只看数据是否命中上面四类死规矩。
- **越权 / 未授权访问**：看的是**是否突破访问控制、拿到本不该拿的资源**，与数据敏不敏感无关。

## 未授权访问的收取门槛（最常被滥用的筐）

**「接口没鉴权」本身不是可收漏洞。** 要 `accepted`，必须突破鉴权后拿到/干成下面**三选一**：

1. **拿到死规矩内的敏感数据**：身份证照片 / 人脸照 / 身份证号 / 密码哈希（批量更高）；
2. **拿到可直接利用的凭证或拿下系统**：能登录的账密、可用 token/session、getshell
   （上传并**验证脚本可解析执行**）、`actuator`/`heapdump` 里提出可用 DB 口令等；
3. **能未授权执行敏感写操作**：改他人数据 / 删数据 / 改配置 / 发起业务或资金变更，**并有实证**。

### 不够格（即便确实没鉴权，也不收）

- 泄露普通业务/展示数据：反馈记录、招标采购列表、设备信息、订单、统计、姓名电话邮箱等普通 PII；
- 读到「系统初始化密码/默认口令」**配置值**却没实证用它登进任何账号；
- 只能"访问/查看"文件但不能上传可执行、未证明 getshell、未拿到死规矩数据；
- 未授权上传：只传 txt/图片 = "上传点存在"，`ignored`/`deepen`；
  但能上传 **HTML/SVG 到目标自身域名且访问时 `Content-Type: text/html`（浏览器执行 JS）** →
  存储型 XSS 成立，`accepted`；能解析执行脚本 → getshell，高危。
  （传到 OSS/第三方域或强制下载头不算）

## 写 / 删 / 改 接口的实证门槛 ★核心

`update` / `delete` / `save` / `remove` 这类**最容易误报**：接口返回"成功文案"不代表真的改了。
只看到成功文案、`data:0`、`对象不存在` —— 属于**半成品**。

### 无害证据协议（必须按这个取证）

**不要删改真实/他人数据。** 三条无害证法，任一条闭环即等同实证：

| 证法 | 怎么做 | 强证据类型 |
|---|---|---|
| ① **自建哨兵** | 用带唯一标识的对象（如 `SRC_TEST_<rand>`）**增 → 改 → 删只碰自己这条**，旁路 GET/列表回读 before→after | `sentinel` |
| ② **鉴权对照** | 未登录/无 token 发同一请求应 401/403，带低权登录态应变 200/授权通过 | `authz_diff` |
| ③ **幂等回写** | 只能碰已有对象时，把原值写回原值，看 `affectedRows ≥ 1` 或授权通过且值未变 | `idempotent` |

旁路回读（`side_read`）也算有力的旁证。反之，仅"成功文案 + 零影响 + 无旁路证据" = **弱证据**，不收。

### 连带纪律

- **不要把写/删 PoC 现场复放一遍来"证明"** —— 既不安全，也会把已经取证到的高危洞降级；
  复放前先看 PoC 里有没有 `DROP TABLE` / `TRUNCATE` / `DELETE FROM` / `rm -rf` / `sqlmap --dump|--os-shell` 这类模式。
- 密码重置类：**必须证明改完新密码能登录 / 状态真实变化**；失败码、空响应、含糊响应一律不算成功。
- 做不到无害取证 → 不要硬来，落成 `deepen` 写清"缺哪一步"。

## 验证码类：必须分清三种

| 情况 | 判定 |
|---|---|
| **图形/算术验证码**明文回显（响应里直接给答案） | `ignored` —— 只破防自动化，不构成实际危害 |
| **短信/手机验证码（OTP）明文回显** | `accepted`（中危~高危）—— 能读任意手机号 OTP → 任意用户登录/改密 |
| **短信/邮箱轰炸**（发码接口无验证码无频率限制） | `ignored` —— 且**不要为了取证真去连发** |

## 疑似后门 / 被黑服务器：要有页面被攻陷的实锤

- 服务器**自身页面**被替换成赌博/色情/彩票、出现 `hacked by`/deface、webshell 可执行 → `accepted`，高危~严重；
- 能发现 webshell 或可命令执行的后门文件 → 严重；
- **不算被黑**：只是引用了图床/CDN/OSS 图片、第三方 JS/CSS/字体/统计，页面仍是原站 → `ignored`。

## 常见半成品清单（Worker 最容易误当漏洞提交）

| 类型 | 为什么不算 |
|---|---|
| 密钥 / Secret / API Key 泄露（含前端 JS 硬编码） | 只发现不算；要**用它实际干成事**（伪造签名调通、越权取数、盗刷配额） |
| CORS 配置过松 | 只看到宽松配置不算；要实证跨域窃取到敏感数据 |
| 无验证码 / 可批量注册 | 单独价值极低；要链到实际危害（撞库、越权、薅羊毛） |
| 第三方 Key 泄露（地图等） | 同密钥泄露：要深挖到实际盗刷 / 越权 / 损失 |
| CAS/统一认证 logout 的 `service`/`redirect` 开放跳转 | 纯 Open Redirect 通常不收；只有实证联动 ticket/token/session 泄露或绕过 SSO 才按实际危害交 |
| 用户名枚举 / phpinfo / 内网 IP / 无意义源码泄露 | 无实际利用，忽略 |

## 定级参考（可对标）

| 档 | 典型 |
|---|---|
| 严重 | RCE / 上传 webshell / 获取服务器权限；重要系统大量敏感数据泄漏（如教务系统注入 dump 学生身份证） |
| 高危 | 普通系统权限 / 普通 SQL 注入 / 批量盗取用户数据 / 绕过认证进后台 / 未授权访问 / 后台管理员弱口令（看登录后实际危害） |
| 中危 | 条件注入 / 任意文件操作 / 水平越权 / 业务逻辑缺陷 / 短信 OTP 回显或可绕过致任意用户登录改密 |
| 低危 | 非核心数据泄露 / 需用户交互的漏洞 |

## 一句话流程

```
发现 → 追问「然后呢？危害实锤了吗？」
     ├─ 实锤            → accepted（贴请求 + 响应 + 命令）
     ├─ 线索真但没打穿  → deepen（写清下一步具体做什么）
     └─ 垃圾/不收/已证伪 → ignored
写/删/改类一律走「无害证据协议」；只发现不利用的一律不算洞。
```
