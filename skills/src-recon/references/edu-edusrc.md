> 什么时候翻这篇：目标是 **`*.edu.cn` / 教育局 / 中小学 / 教育软件**，或操作者说「我要 EDU 的证书」。

## 一、先认清「证书」是怎么来的（别搞错目标）

| 事实 | 含义 |
|---|---|
| 平台 = **教育漏洞报告平台 EDUSRC**（`src.sjtu.edu.cn`） | 收录范围：教育部 / 各省教育厅（教委）/ 各级教育局 / **学校** / **教育相关软件** |
| **不收录**：培训机构、教育企业、非教育主管部门管辖的站点 | 打错单位 = 白干 |
| 命中 → **Rank 积分 + 金币**；金币在礼品中心兑换 | **「原创漏洞证书（XX大学版）」是礼品**，按金币/条件兑换 |
| 审核周期约**半个月**（严重件优先） | 出证书是**积少成多**的事，不是一锤子 |
| 提交规范：**完整关键 URL**（不能只写主域名）+ 图文细节 + 影响/利用方式 + 修复建议；**不公开** | 报告的字段口径见本文 §六 |

**由此推出的策略**：证书 = 「**多个被审核通过的中高危及以上的洞**」。
→ 追求 **可复现、判据清晰、单点危害成立** 的洞，而不是「面很大但说不清」的扫描结果。
→ 单位归属选错会直接被退回，**提交前先把「这个资产属于哪所单位」查清**（平台单位搜索框）。

### 一·一 官方定级标准（决定「报什么最划算」）

平台 Rank 分 **0~10**，**金币与 Rank 1:1**（1 rank = 1 金币）：

| 等级 | 分值 | 典型（摘自平台原文） |
|---|---|---|
| **严重** | 9~10 | 重要服务器 RCE / webshell；**重要系统能获取大量信息的 SQLi**；目标单位核心机密 |
| **高** | 7~9 | 普通系统 RCE；**任意账号密码修改**、重要业务配置修改；普通系统 SQLi、用户订单遍历；**绕过认证直访管理后台 / cookie 欺骗**；**后台管理员弱口令、服务未授权访问** |
| **中** | 4~7 | 一定条件下的注入/getshell；**任意文件读写/下载/敏感文件读取**；**水平权限绕过**（改用户资料、执行用户操作） |
| **低** | 0~4 | 非核心数据获取；条件严苛才能拿核心数据；**需交互的 XSS/CSRF/点击劫持** |

**★ 会降级的七种情况（同一条结论可能被压一级）**：① WAF 导致**说不清利用方法**；② 单位已知未修；
③ 需特定条件/偶然触发；④ **同一单位多处相似漏洞**；⑤ **恶意夸大危害**；
⑥ **非同一单位但利用方式相似**（→ 批量提交「通杀」会被按低档算）；⑦ 已公开的通用型漏洞。

> **一条被反复验证的判据（多篇 WP 都点到）**：EDU 的评级文字里处处是「**敏感信息泄露**」。
> 不必只盯 getshell/RCE —— **未授权读到大量师生 PII** 或 **任意用户密码重置/登录** 就是高/中危主力。
> 但注意上面 ⚠「同一单位多处相似」「非同一单位利用方式相似」：**别把 10 个学校的同一模版洞当 10 个洞报**。

### 一·二 证书门槛（选校就选「门槛低 + 中危即可」的）

证书在礼品中心按**金币**换，且**不同学校的证书兑换条件不同**（第三方整理的 25 校口径，2026-10-04；
以平台礼品中心实时说明为准）：多数写「**中危或以上级别漏洞**」，也有低门槛：

| 低门槛（参考） | 条件 | 金币 |
|---|---|---|
| 新疆交通职业学院 | **1 个漏洞** | 6 |
| 泰山学院 | **1 个漏洞** | 10 |
| 长春理工大学 / 河南农业职业学院 / 上海外国语大学 | 中危或以上 | 10 |
| 淄博师范高等专科学校 / 常熟理工学院 | **2 分或以上** | 11 / 10 |
| 山东理工大学 / 上海商学院 / 广东工业大学 | 中危或以上 | 15~20 |

→ **策略**：目标是「**把自己账号能触及的资产里，凑出 1~2 个中危**」——
中危门槛低得多（任意文件读取、水平越权、后台弱口令、未授权接口），
而高危（任意用户登录/密码重置、绕过认证进后台）往往就长在隔壁面。
**抢证书窗口很短**（有实战记录：从新证书发布到提交 < 5 分钟），看到新上系统/新校名就抢。

> 选系统与厂商的客观依据见 `edu-系统级攻击面.md` §一（Pig4Cloud 全链）与 `tools/edu_index.py vendors`。

## 二、高产出洞型排行（EDU 实盘 + 本地 PoC 支撑）

按「出洞概率 × 定级高度」排序。括号内是**本机 `poc` 库实测命中数**（2026-10-04，`poc "<词>"`）。

| # | 洞型 | 为什么在 EDU 高产 | 本机支撑 |
|---|---|---|---|
| **1** | **统一认证 / CAS / SSO 未授权接口** → 账号枚举 → 密码 Hash 泄露 → 接管 | 全校所有系统共用一套认证，**一个洞影响面天然是「全校」**；接口常无鉴权 | 本地 PoC：`CAS` **83** · `统一身份认证` **4**；人工接口 fuzz 是主路径 |
| **2** | **教务/学工/研究生系统 越权（改 `xsid`/`uid`/`id`）+ 脱敏字段抓包回显** | 个人信息页打了码，但接口返回原文；`/user/all` 这类路由最常漏鉴权 | 联奕 **2** · 正方 **9** · `URP` **10** · `智慧校园` **9** |
| **3** | **信息泄露链**（`.git`/`.svn`/备份包/`sourcemap`/`phpinfo`/`actuator`/接口文档/配置文件） | 「更土的路」在 EDU 命中率最高，且常直接给密钥 → 升级成高危 | `dumpall`/`githack`/`svnexploit`；`4-信息泄露与密钥.md` |
| **4** | **OA / VPN / 中间件已知 CVE** | 高校自负运维，补丁常年滞后；泛微/致远/通达/深信服是重灾区 | `用友` **904** · `泛微` **309** · `致远` **158** · `通达` **131** · `Spring` **117** · `VPN` **92** · `宏景` **61** · `锐捷` **40** |
| **5** | **小程序 / APP 侧 API**（签名形同虚设 + 角色校验缺失） | PC 端修了、移动端没修；签名可绕 → 学生角色拿到全量数据 | `小程序渗透.md` + `wxapkg.py` + `authzdiff.py` |
| **6** | 业务逻辑 / 竞态（选课、评教、缴费、报销、预约） | 扫描器结构上看不见 | `3-业务逻辑.md`；`race-conditions.md` |

> **先把 #1/#2 做透**：EDU 的高危 90% 出在「认证」与「越权」两条线上。

### 二·一 EDU 特有的五个「出分点」（多篇实战 WP 交叉验证，2026-10-04 补）

| 洞型 | 打法（具体到抓什么包） | 判据 |
|---|---|---|
| **忘记密码流程的前端校验绕过** ★最易漏 | 走「忘记密码→输账号→需手机验证」，**抓返回包**逐个试 `false→true` / `code 0→1` / `msg 1→2` → 前端据该字段放行 → 直接改密码接管 | 改到**标定账号**（自建第二个账号做对照）才算；**不去真改陌生人的密码** |
| **用户名枚举** | 注册/找回密码处提示“用户不存在”：返回字段（`msg:1/0`）能区分存在性 → 用姓名/学号字典枚举 | 枚举出真实账号 = 中危；**配上默认密码登录成功**才是高危 |
| **默认密码 = 身份证后六位 / 学号** | 登录页公告常写“默认密码为身份证后六位”；学号/身份证从公开信息（录取名单、官网公告、报告厅）收集 | 登录成功 + 能跳到其他系统（教务/学工）= 高危，写危害时要写清“全校默认凭据” |
| **`user/all` 类全站未授权路由** | 注册一个（哪怕无权限）账号后**翻代理历史**，找响应体异常大的路由；典型 `user/all` 无鉴权 → 全站手机号 + hash；登录框**不校真实密码**（随便填都能进） | 未登录/任何账号能读全站用户 = 高危；**只验 1 条** |
| **凭据复用（旁站→主站 SSO）** | 同校旁站（教学/实训/图书馆）弱口令或 MD5 可破 → 拿账号去主站 SSO 试 | 登录成功即有效；报告要注明是「复用」而非主站自身缺陷 |

### 二·二 选它之前先看公开数据（本机已落成工具）

EDUSRC **两张公开表不需要登录**，但能直接回答「现在什么级别能被确认、哪些厂商有洞」：

```bash
python3 tools/edu_index.py fetch            # 拉 /list/ 最新页 + /rank/company/ 全榜 → work/edu/
python3 tools/edu_index.py show            # 等级分布 + 确认节奏（例：2026-10-04 实测 高危5/中危10）
python3 tools/edu_index.py vendors --top 40  # 548 家教育软件厂商榜（修复率高=产品确实有洞且被收录）
```

→ 用法：**厂商榜**选出“有洞且被确认过”的系统（如齐治/职迅/万雍/博达）→ `poc "<品牌>" --usable`
→ 拿厂商产品指纹去匹配学校资产 → 走对应品类册的判据。

## 五、判据（EDU 语境下什么叫「打穿」）

| 结论 | 必须同时满足 |
|---|---|
| **未授权访问（accepted）** | 无任何凭据的请求 → **返回了本该鉴权才能看到的业务数据**（不是 200、不是登录页、不是空数组）；证据 = 请求 + 响应 + 一条样本 |
| **越权（accepted）** | `authzdiff` 三方对照：**身份 A 能拿身份 B 的数据**；A、B 都由操作者提供/授权，**只取 1 条** |
| **信息泄露（accepted）** | 泄露内容**本身可自证危害**（密钥/凭据/源码/大批量 PII 的字段结构），且**只证明「能拿到」** |
| **不算（ignored）** | 只回 `200`、登录页跳转、报错差异、`data:null`、会话内自取（如按 cookie 取自己数据）、版本号外露 |

★ **红线（EDU 站点普遍脆弱，这条比技术更重要）**：
1. **限速 ≤2 rps，单目标并发 1**（`../references/对抗-别把IP打没.md`；教育网出口一旦被打挂 = 事件）
2. **禁止脱库/删库/批量拉取**：证明能读全表就停，报告写「可读（**未**遍历）」+ 1 条样本
3. **禁止写/改/删真数据**；要证明写类只能走无害证法（自建哨兵 / 401-403 对照 / 幂等回写原值）
4. **不碰判定源**（把马/后门/改配置一律不做）；不做 DoS/压力测试
5. 遇到**考试期间 / 选课期间**的业务系统：只做**被动与只读**，不触发任何写路径

## 五·一 判定纪律：三条机器可查的坑（2026-10-04 三校实盘，同一晚各踩一次）

| 坑 | 后果 | 硬判据 |
|---|---|---|
| **跟随跳转下结论** | 指纹/页面大小全错：`www.cslg.edu.cn` 被打上「致远A8+正方教务」（标签来自 302 目标）；`debot/dzrgjy/exw` 被当成「所有路径回同一个 59KB 大页」（那是 302 后 CAS 登录页的尺寸） | **判本体时禁用跟随跳转**（`curl` 不带 `-L`，urllib 不开 redirect）；看 302 的 Location 而不是它的终点 |
| **把 502/0B 当存活或当“后端挂了”** | 虚报资产/误判原因：经本机 Clash（`127.0.0.1:7897`）访问不可达或不存在目标，统一回 `502/Content-Length: 0` 或 TLS `unexpected EOF`，**与 NXDOMAIN 响应逐字节相同** | 只有「**拿到非空响应体 且 与假路径 md5 不同**」才算存活；其余记「未判定」（`probe.py` 标 `unreachable`） |
| **没做 catch-all / 软404 判定** | 把诱饵页/统一壳页当发现：`dns1/vpn1/cj*/ehall/bgxt` 全路径同一响应；`atc/hqch/charter` 假路径 200 但 md5 相同 | 每个「发现」先拿 3 个假路径（`/a1b2c3q7` `/zzz9` `/nonexistent-xyz123`）比 md5；相同就不是发现 |

## 六、提交口径（写报告时照这个填）

平台要求「完整关键 URL + 图文 + 影响/利用 + 修复建议」。落到本机就是 `fgs fact-add` 的字段
（`board/schema.md`「SRC 结论字段约定」）：

```bash
# ★ 旗标名是 --proof-kind（连字符，不是下划线）；确认坐实要用 --confidence verified
fgs fact-add <pid> "<一句话结论>" --confidence verified \
  --verdict accepted --severity high --proof-kind authz_diff \
  --action verify --target <host> --tool "curl"
fgs verify <pid> <fact-id> --from <原始输出文件>   # 关键值必须逐字出现在证据里
fgs gate <pid>                                      # 能不能报，机器说了算
```

报告骨架（`work/<pid>/REPORT.md`）：

```
1. 单位与资产归属（先查平台单位搜索，别填错）
2. 漏洞标题：<系统> <洞型（未授权/越权/SQLi）>
3. 完整 URL + 复现步骤（curl 原文，含请求头/体）
4. 响应证据（截取关键片段；PII 打码，只留 1 条样本）
5. 危害说明（能拿到什么 / 能做什么 —— 写清楚，别夸大）
6. 修复建议（鉴权中间件 / 参数化 / 最小权限）
7. 附：Skip 清单（证伪的路线，证明你判过）
```

> **"新出现的洞"怎么找**：优先看**新上线的系统**（新域名/新路径/新小程序）——
> 高校每学期开学前后会新上迎新、选课、离校、缴费系统，**新系统鉴权最糙**。
> 判据：证书透明日志（`crt.sh`）按时间倒序、`gau` 的历史 URL 与新路径差集、
> 开学/毕业季新上线页面。这条与「只在老系统上撞已修 CVE」相比，出洞率差一个量级。

## 七、停止条件

- 同一条路径试 **3 次无反应**（无回显、无差异、无报错变化）→ 换攻击面（入口/参数/协议层），
  不是换 payload 细节；在 Fact 里写「已证伪 + 试到哪」。
- 单目标累计 **≥30 分钟无新 Fact** → 换资产（同校换系统，或换校）。
- 已拿到一条实锤 → **先写报告**（`fgs gate` 过闸），再决定要不要继续同一目标。
