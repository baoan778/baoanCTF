## 六·五、竞赛模式（限时 / 多题：**少即是多**）

> 来源：湾区杯 Agent 赛道拿第一的队伍「只用 ZCode + 一个定时任务，**没有任何 skill、资料库**」；
> Rotom 作者复盘原话：「原来这个才是少即是多」。技能数量不是能力，**可发现性**才是。

限时比赛按这套开，别把平时的全套都摊开：

1. **只加载当前题型的 skill**（web/pwn/re/… 挑一个），别把 15 个都摆进来 —— 上下文就是预算；
2. **广度优先**：多题时先"每题一个 worker"，再给难题加人（别一上来把并发全砸在一道题上，
   比赛前几分钟出简单题的收益最高）；
3. **增援走黑板**：一个人做不完，就在 Fact/Step 正文写 `[请求增援] 需要 N 个 agent: 谁干什么`，
   主会话 `fgs aid <pid>` 看清单再派活（worker 之间不直接通信）；
4. **剩余时间进决策**：临近结束偏向**最短利用路径**，不要开需要长期侦察的新方向；
5. **平台限流 ≠ 答错**：`SUBMIT_BUSY` 只重试，**别改已经正确的 flag**（见 `board/schema.md`）；
6. **被判"卡住"就换攻击面**：`fgs next` 会提示「连续 3 个 Step 无 verified 产出」—— 换入口/参数/协议层。
7. **快就是分**：不少赛事按「提交即时锁定 + 排位衰减」计分（TCH 第二届：第 1 名 +20%，**11 名后 −10%、21 名后 −50%、31 名后 −80%**；**看一次漏洞提示扣 10%**）
   → **先秒简单题、少看提示**；一道题超过时间盒就换，别死磕；
8. **"何时停"要有判据**（实测短板：AI 不知道自己测全没有）：收口前必须落一条结论 ——
   要么 verified 的「打穿了」，要么**死路论证 Fact**（逐条写清哪些入口/参数/协议层已被证伪）。两条都没有 = 没测完，不许收工；
9. **AI 的边界是「已知的未知」**（yhy0）：套路题/已知 CVE/框架漏洞放心让 agent 冲锋；
   **完全孤立的业务逻辑、需要人情/物理世界判断的**（谁的生日、内部暗号），要人给线索；
10. **断网 / 离线场景**（线下赛、隔离网）：① 本机跑代码专精小模型（实测够用，如 Qwen3.8-27B 级）；② 只用离线资源（`poc` 11290 条索引 / `tools/knowledge` / `skills/*/references`）；③ provider 在 `models.json` 里指本地 baseUrl —— 不依赖云端也能打。

### 编排者的 6 条失误必须机器可判（2026-09-30 run 23966 血账）

上次 20100/23000（87.4%），缺口全在多阶段链，但**真正的失误全在编排层**（我自己），
而且全都写进文档了却没拦住 —— 所以它们必须有工具兜底，不能靠记性：

| 失误 | 机器判据 |
|---|---|
| 默认 30 分钟超时砍断 lane | 派 lane **必设 `timeoutMs`**；`radar.py` 报「N 分钟无产出」 |
| 被污染的会话反复 resume（白烧 25 分钟） | 同一会话**第 2 次**同类 API 错 → 换全新会话 |
| 末段 6 条 lane 打同一目标（后 2 小时只 +1200） | `radar.py` 报「同目标并行」+「活跃 lane > 末段上限」 |
| 自算报分 19200（平台 18900） | **只报 `run-status` 权威分**，自算值不出口 |
| 名额治理晚了 1 小时；据点被自己的清理器清掉 | 第一轮就建 `slot.sh`+`janitor`+`foothold.py` |
| 熵增：检查表只是文字，下次没人读 | 跑完当天把「检查表」升级成**可执行工具** |

→ 多 lane / 多目标场景（跑分、`fgs swarm`）**每次检查点跑**：
`python3 <工作区>/radar.py --check`（权威分/名额/lane 台账/并行/据点/指纹，一次看尽）。
收敛曲线写死在工具里：**剩余 ≥4h 上限 6 条 lane / 2–4h 4 条 / 90–120m 3 条 / 30–90m 2 条 / <30m 1 条**。
