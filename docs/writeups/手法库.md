### PNG IHDR 尺寸篡改 + CRC 未更新（图片取证 / bin 结构类 Misc）

**触发条件**：PNG 能打开但内容明显被裁掉/错位、`file` 报的尺寸与观感不符，或校验时发现某个 chunk 的存储 CRC 与重算值不等。

**做法**：
1. 逐 chunk 解析并重算 CRC，定位「存储 CRC ≠ 重算 CRC」的 chunk。篡改者常只改数据、不改 CRC —— 于是**存储的那个 CRC 就是原始数据的正确 CRC**，可直接当反解锚点。（参考 `work/broken_ihdr/walk.py`）
2. 若被改的是 `IHDR` 的宽高：解压全部 `IDAT` 得真实像素流长度 `L`。对 8-bit 非隔行 RGB（colortype=2）成立 `h*(1+3w)=L`；枚举 `L` 的因子 `k=1+3w`（须 `k ≡ 1 (mod 3)`），得候选 `(w,h)`。
3. 把候选 `(w,h)` 连同其余 IHDR 字段（depth/colortype/interlace 通常未变）重算 CRC，与锚点比对 —— 命中即真实尺寸。
4. 把 `0x10:0x1D` 的 IHDR 数据改回真实尺寸、`0x1D:0x21` 的 CRC 写为正确值，另存为 `fixed.png` 再读 flag。

**通用化**：任何「校验字段未随数据更新」的格式，未更新的检验值 = 原始正确值，可作不变量反解被篡改字段；思路是先找格式内部能闭合的等式约束，再用独立校验收窄到唯一解。

**踩坑**：底部文本框这类「flag 在边缘」的题，缺陷尺寸会把边缘裁掉，修复前 OCR 读不到；OCR 别死守 `--psm 7`，整页 `psm 3` 往往更稳（本项目实测 psm=7 糊、psm=3 逐字正确）。

**坐实**：✅ 本项目 **flag 已解**（真实尺寸反解成功，`work/broken_ihdr/walk.py` 可重跑复现）。

**来源**：broken_ihdr

### 只有一个 printf 可用时：GOT[puts] → system + `sh;` 前缀（PWN / format string）

**触发条件**：格式化字符串题、**没有栈溢出**、程序只给一两次 `printf(buf)`，`buf` 之后会被 `puts(buf)` 之类「拿我们 buffer 当参数」的函数再用一次；二进制里没有 `system` 但有 libc。

**做法**：
1. **第一段 buffer 开头写成 `sh;`**，后面接 `%N$s` + 尾标记 + padding + `p64(GOT_puts)`（地址**必须放末尾**，放开头会被地址里的 `0x00` 把 printf 截断）。
   - 这一段同时干两件事：`%N$s` 读出 `GOT[puts]` → libc base；开头的 `sh;` 让这个 buffer 之后能直接当命令行用。
2. **第二段**（若有第二次输入，或就在同一段里）手搓 `%hn` 把 `GOT[puts]` 写成 `system`：
   只写**低 4 字节**就够 —— system 与 puts 在同一个 libc 映射里，高 4 字节相同；这样 payload 能塞进 64 字节的读入上限。
3. 程序随后的 `puts(buf)` → `system(buf)`，而 `system()` 实际执行 `sh -c "sh;%N$s..."`：
   **分号让 `sh` 成为独立命令**，内层 `sh` 的 stdin/stdout 就是 socket → 直接拿 shell（剩下的 `%N$s...` 只是随后一条报错的无效命令）。

**校验两条**（不对就别往下写 exploit）：libc base 的末三位必须是 `000`（页对齐）；泄漏解析用**固定尾标记**，别用 `|` 之类分隔符（泄漏字节里可能就有 `0x7c`）。

**坐实**：✅ 本项目 **flag 已解**（0xGame FMT 题，2026-10-01）；已工具化 → `pwnkit fmt probe|leak|write`
（**手法→工具的转化本身就是坐实的证据**：能被工具化的说明它被跑通过多次）。

**来源**：pwn-name

**触发条件**：要在 PC 上拿微信小程序的源码。**老教程的路径是错的**。

**做法**：
1. **路径**（WeChat 4.x / "Weixin" 与 3.x 完全不同）：
   `%APPDATA%\Tencent\xwechat\radium\users\<hash>\applet\packages\<appid>\<版本>\*.wxapkg`

   然后你在后面白查两小时。
4. 工具：`py tools/wxapkg.py decrypt|unpack|scan`（`selftest` 5/5，合成包往返 + 路径穿越防护）。

### 服务分发器的存在性 oracle：用错误码区分「服务在不在」（SRC / API）

**触发条件**：接口长成**单端点 + 参数分发**的形状（如 `/guard/{module}/touch/baseController?qrt={service}`）。
这类网关背后是一堆内部微服务，**服务名通常不写在前端代码里**（运行时下发）。

**做法**：
1. 先找**可判定的错误码分界**：发一个明显不存在的服务名 → 记录错误码（本例 `2003 资源不存在或接口不存在`）；
   再发一个已知真实的服务名 → 记录（本例 `2009 参数错误`）。
   **两者可区分 = oracle 成立**（`2003` ⇒ 不存在；`2009`/`0` ⇒ 存在）。
2. **但不要盲猜服务名**。本项目回测 5 个猜名 **0 命中** —— 正确姿势是**翻页面收集**：
   每次页面加载都会暴露它依赖的服务名（浏览器抓流量，见上一条）。
3. 关键判断：**未登录调用返回的是业务错误码（参数错误）而不是 401/403** →
   说明该服务**接受未鉴权调用，只缺参数** → 值得继续试参数。

**坐实**：机制实测成立（可复现）· **未出洞**（走到了「服务可达」这一步，没拿到他人数据）。
本项目：oracle 判定式实测成立；`t_go_queryUserRiskLevel` 未鉴权返 `2009` 而非 401。

**通用化**：任何「单入口 + 名字分发」的系统（GraphQL operationName、gRPC service、
云函数名、MQ topic）都适用这个 oracle 形状 —— **先找可区分的错误码，再决定枚举策略**。

**来源**：miniapp-qunar

### 自研分帧协议：写确定性 `deframe` 脚本当 byte-exact 证据（逆向 / 自定义 wire 协议）

**触发条件**：服务端把输出也用**自己的分帧协议**包起来 —— 原始 socket 回包里明文**不连续**（能看到帧头 `\x08!`、`\x08"`、长度字段穿插在明文中间）；或题目给出的是「原始收发 hex 转录」而非明文。

**做法**：
1. 先从二进制里把**输出侧的编码路径**也逆出来（别只看输入侧）—— 逆向时用 `fwrite`/`write` 的 `@plt` 交叉引用找 `send` 类函数，确认输出的分帧规则与输入同构。
2. 写一个**只依赖标准库、确定性、可重放**的解帧脚本（不要手抄 hex 解码），输入是留档的原始回包文本。例：`work/ctfplus-arcade/deframe.py`（扫 `0x08` 帧，按 op 高位取 `insn[2:8]`/`insn[1:8]` 拼接）。
3. 拿**解帧脚本的输出**作为 `fgs verify` 的证据文件，而不是原始回包 —— 原始回包里明文被切断，`verbatim` 校验会失败。
4. 用同款脚本在**本地进程**上回放一遍（自己注入环境变量），确认输出协议一致，双重支撑结论。

**踩坑**：不要因为「原始输出里能看到一半 flag」就认为证据够了；`fgs verify` 要的是逐字连续。也别直接用 hex 手拼明文 —— 手拼不可重放，且容易在补零/截断上出错。

**坐实**：✅ 本项目 flag 已解 —— `py deframe.py raw-output.txt` → `0xGame{b9293d2b-545c-44b2-b4b0-4a6c5ebaf52f}`（图上 `f003 [verified]`，`work/ctfplus-arcade/deframed.txt`）。

**通用化**：任何「自定义 wire/framing 协议」的逆向题（游戏封包、私有 RPC、串口/总线帧）都适用：输出侧常与输入侧同构，先把**两端**的编解码都逆出来，再用确定性的重放脚本固化证据。

**来源**：ctfplus-arcade

### stripped ELF：用 `@plt` 交叉引用定位定长帧协议函数（逆向 / 无符号二进制）

**触发条件**：`file` 报 `stripped`、无符号；程序是一个**网络/IO 服务**（`getenv` 里有 `FLAG` 之类、循环读 `fd 0`）。

**做法**：
1. `objdump -d` 全量反汇编落盘（`dis.txt`）。
2. 先看 **`_start`**：`lea rdi,[rip+...]` 传给 `__libc_start_main` 的第一个参数就是 `main`（`stripped` 也不会变）。
3. 在 `main` 里找 **`read@plt` / `fwrite@plt` / `getenv@plt` / `memcmp@plt`** 的调用点，顺藤摸到「读报文」和「发结果」两个函数。
4. 判据信号：**「循环读满固定 N 字节」**（`cmp QWORD [rbp-x],N-1 / jbe loop`）几乎必是**定长帧协议**（本例 N=9 = `0x08` + 8 字节指令）；随后按 op 高位分派的分支表就是报文的三种类型。
5. 输入侧解出来的编码，**再到输出侧找同构实现**（通常是一对 `encode`/`decode`），确认服务端输出也用同款分帧。

**坐实**：✅ 本项目 flag 已解 —— 靠 `mov DWORD [rax],0x1/0x2/0x3` 三分支定位 `insn_decode`、靠 `0x19f0` 的 `mov WORD [rbp-0x56],ax`（type2 首批 6 字节计入 `written`）定出分片起点；`work/ctfplus-arcade/dis.txt` 可重跑。

**通用化**：所有 stripped 服务端二进制逆向的第一步都一样 —— 别从 `0x1180` 盲读，先用 `@plt` 交叉引用 + `_start` 定位 `main` 与 IO/协议函数，再按「固定长度读取 / 分支表」认协议形状。

**来源**：ctfplus-arcade

### ZipCrypto + Store：把「可推导的文件头」当 16 字节已知明文打 bkcrack（Misc / 加密压缩包）

**触发条件**：`zipinfo -v` 或 `7z l -slt` 看到 `file security status: encrypted` **且** `compression method: none (stored)`。
Store = 文件原文没被压缩 —— 只要知道（或能推导）任意条目的前 ≥12 字节明文，就能直接套 ZipCrypto 的 Biham–Kocher 已知明文攻击。题面常拿「Store vs Deflate」点题。

**做法**：
1. **先想「哪个文件的前 16 字节是格式规定的」** —— pyc 头、PE `MZ`、ELF `\x7fELF`、PNG `\x89PNG`、SQLite `SQLite format 3\x00` 等。
2. Python 3.13 **时间戳式** pyc 头 16 字节可全推：`magic(4) f30d0d0a` + `flags(4) 00000000` + `源 mtime(4)` + `源大小(4)`。
   - **源 mtime 从 zip 里拿**：中央目录 `0x000a`（PKWARE Win32）extra 子字段前 8 字节是 NTFS FILETIME（100ns since 1601）—— 换算成 Unix 秒即 mtime（本例 `0x01DD3BAA280B3EE8` → 1788442989）。
   - **源大小从 zip 拿**：该条目（pyc 对应的 `.py`）的未压缩大小；同包 `locked.py` 的 `uncompressed size` = 488。
3. 写 16 字节原始明文文件，打攻击：
   ```bash
   bkcrack -C secret.zip -c locked.cpython-313.pyc -p pyc_known_plaintext_16b.bin -o 0   # -o 0 = 明文对齐密文 offset 0
   #     -> Keys: 64917537 61b24fcf b564419c
   bkcrack -C secret.zip -c locked.cpython-313.pyc -k <k1> <k2> <k3> -d locked.pyc
   ```
4. **必做 byte-exact 校验**：解密产物重算 `zlib.crc32` / 长度，与 zip 中央目录记录的值比对，一致才算成功（`file` 回读 magic/尺寸也能交叉印证）。
5. 拿到内部密钥即完成，**无需口令**。

**踩坑**：
- 别去**猜源码文本**当已知明文（如 `from secret import flag\n`）—— 差一个空格/换行就不收敛，跑满全部 Z 值也是 `Could not find the keys.`。优先选**格式决定**的头部，不要选人类书写的内容。
- `--continue-attack` 复放**不会重现 Keys**（checkpoint 跳过已找到解）—— 原始 Keys 证据要单独留档。

**坐实**：✅ 本项目 flag 已解 —— `work/zipdoctor/solve.py` 复现出 `0xGame{pyc_1s_n0t_s0_s3cur3}`；解密 pyc crc32 `0x222b4190` 与 zip 记录一致（图上 `f002`/`f003` verified）。

**通用化**：任何「流密码（ZipCrypto/PPTP/…）+ 有格式头部或冗余明文」的场景都适用；核心是把「已知明文从哪来」变成可离线构造的确定量，而不是等对方吐一段已知内容。

**来源**：zipdoctor

### RSA 模数是经典合数（Fermat 数 F8 等）：查已知分解，别硬分解（Crypto / 退化 RSA）

**触发条件**：从二进制/pyc 反汇编里读出的 RSA 模数 `n` 长得可疑 —— 如 `2**256+1`、`2**k+1`、`10**k+1`，或本身就是某个知名常数。代码里若出现 `p='??'`/`q='???'` 占位、`getPrime` 只 import 不用，基本就是故意的。

**做法**：
1. 认出 `n`：`2**256 + 1` = 第 8 个 Fermat 数 `F8`。**F8 是合数**，有公开已知分解（Brent & Pollard 1980）。
2. 直接查/记已知分解（本题）：
   ```
   2^256+1 = 1238926361552897 × 93461639715357977769163558199606896584051237541638188580280321
   ```
   （51-bit × 206-bit；即便本机 `py` 里用 Pollard-rho/ECM 也能秒出，但查表更快。）
3. 其余照常：`phi=(p-1)(q-1)`；`d=pow(e,-1,phi)`；`m=pow(c,d,n)`；`m.to_bytes(...)`。
4. **回代校验** `pow(m,e,n)==c`；flag 若含明确前后缀（`0xGame{...}`）可再核一遍首尾。

**坐实**：✅ 本项目 flag 已解 —— `work/zipdoctor/solve.py` 断言 `p*q==n` 并解出 `0xGame{pyc_1s_n0t_s0_s3cur3}`（图上 `f004` verified）。

**通用化**：见到「模数太整齐」先怀疑它是不是知名常数/低指数 Fermat 数；RSA 题的难点常在「识别退化结构」而不在计算 —— `n` 是否素数、是否有小因子、是否是 `2^k+1`，都先试一遍再决定是否上重型分解。

**来源**：zipdoctor

### zip 上传解压「千层套路」：`../` slip 到白名单落点 + `.htaccess` 特例 + `<?=` 短标签图片马（Web / 文件上传）

**触发条件**：上传 zip → 服务端解压 → 回包逐 entry 打印「已解压/拒绝(原因)」。看到 hint 明说某个**具体绝对路径**可访问（如「你只能直接访问 /var/www/pub 目录」）、且回包会**逐条告诉你每层为什么拒**——这就是出题人把每层校验设计成可枚举的「千层套路」题。

**做法**（按本项目的七层，逐层给可枚举探针）：
1. **先测绘，别急着打**：一个 zip 塞多个 entry，每个只探一种形态（后缀、魔数、落点、`.htaccess`、标签、关键字），让回包逐条回你原因。
2. **落点是关键**：`../` 层数 = 解压目录到白名单落点的相对深度。落点常在**解压目录的上三级之外**（本题解压到 `uploads/<name>.zip/`，白名单落点是 `/var/www/pub` → 用 `../../../pub/x.png`，**两级 `../../pub/` 只到 docroot 下、不在白名单会被拒**）。
   - ★ 若绝对路径 entry（`/var/www/pub/x.png`）回包说「已解压」但 GET 不到，是**校验按绝对路径放行、`extractTo` 却拼在解压目录内**——校验/提取不一致，**无用**，改用相对 `../`。
3. **找配置文件特例**：`.htaccess` / `.user.ini` 常被单独放行（本题只放 `.htaccess`，且要求内容恰为一行 `AddType|AddHandler|SetHandler application/x-httpd-php .扩展名`，禁子目录、目标已存在则拒）。用它把允许的图片后缀注册成 PHP：`AddType application/x-httpd-php .png`。
4. **图片马**：真图片魔数开头（绕魔数检查）+ 紧跟 `<?= ... ?>`（绕「仅 `<?=`」）+ payload 避开黑名单。**先 GET 一次确认 `.htaccess` 生效**（如 `/pub/<探针>.png` 返回 `<?=1+1?>` 的执行结果 `2`）。
5. **黑名单活口**：关键字黑名单常是**子串匹配**（`exec` 会连 `shell_exec` 一起拦）；把 `system/passthru/eval/assert/file_get_contents` 等一律列出后，找**没在名单上的等价函数**。读 flag 只需文件读取族：`readfile` / `scandir` / `glob` / `print_r` 常是活口。禁 `$` 时连变量/动态函数名拼接都堵死（`$f='sys'.'tem'` 也拒）。
6. **flag 路径未知**：先用 `<?=print_r(glob('/*'))?>` 或 `<?=print_r(scandir('/'))?>` 列根目录拿到真实文件名（常带随机 hex），再 `<?=readfile('/flag_<hex>.txt')?>`。

**踩坑**：
- **回包文案「已解压」≠ 文件落在你以为的地方** —— 绝对路径 entry、`../../` 差一级，回包都可能说「已解压」；**必须用一次 GET 证实落点**。
- **`.gif`/其它后缀注册不一定生效**：生效的后缀以当时 `/pub/.htaccess` **实际注册的那一个**为准（本项目实测注册 `.png` 生效、`/pub/x.gif` 仍被静态回吐原始 `GIF89a<?=7*7?>`）。也别把「目标已存在」误当成成功——那是上一轮留下的 `.htaccess`。
- 禁 `$` 出题点很常见，别把 `$_GET` / `$_ENV` 回调当出路。

**坐实**：✅ 本项目 **flag 已解** —— `work/upload-layers/lanes/lane2.md` §5 的 xxd 逐字节抓到 `0xGame{a045a69f-41fa-4058-9670-2323460fc9e0}`（偏移 `0x09` 起，末尾 `45` = `readfile()` 返回字节数，自洽）；离线形态校验脚本 `work/upload-layers/exp_replay.sh --selfcheck` 可重跑。

**通用化**：凡「上传 → 解压 → 多次归一化校验」的题，本质是**多层独立白名单的乘积**；漏一层即可。测绘时优先找**出题人主动放行的特例**（`.htaccess`、特定落点、短标签），那通常就是预定路线；再在被允许的语法子集里挑**黑名单没覆盖的等价函数**。

### 二阶注入：注册→登录→改密三件套 + 自造「无 sleep 布尔 oracle」（Web / SQL 注入）

**触发条件**：登录/注册等写入口都打不动（转义严实）、常规 union/sleep 全失效，但站点有「注册 → 登录 → 改密」这类**把先写进去的字段再读出来二次使用**的功能。写入点转义 ≠ 使用点转义——正是二阶注入的信号。

**做法**：
1. **排除一阶**：登录用户名/密码、`list` 类列表页、注册 INSERT、改密 SET 子句五个位置逐一试 `' OR SLEEP(3)#`。只有「注册进去的 `mail` 在改密时再次使用」这一个点没排除，就是它。
2. **时序探针确认**：注册 `mail=t1' OR SLEEP(3)#`，登录后改密，看 `info.php` 耗时是否 `time=~20s`（3s × 表里行数）。
3. **自造布尔 oracle**：把改密语句改造成条件判定——注册 `mail=<base>' OR <COND>#`（密码 P0），改密把密码置 P1，再用同一 mail + P1 重登：`302 = COND 真`、`200 = 假`。4 请求/bit，不依赖时间，比 sleep 盲注稳且快。
4. **先量约束**：mail 列常 `varchar(60)`，超长被静默截断。用 `MID`（3 字符）替代 `SUBSTR`（6 字符）、前缀只留 2~4 字符，脚本里 `assert len(mail)<=60`。
5. **读文件**：`@@secure_file_priv` 为空时 `LOAD_FILE('/key')` 可读任意路径；`ORD(MID(LOAD_FILE('/key'),i,1))>mid` 二分逐字节。
6. **每个值反证**：精确匹配 + 前缀匹配 + 反向对照（`='flag_xxx'` True、`LIKE 'flag_xxx%'` True、`='flag_xxc'` False）。

**坐实**：✅ 本项目 **flag 已解** —— `work/cisp-pte-35581/evidence-key.txt` 里 `LOAD_FILE('/key')='flag_nisp_cbe81b'` 精确匹配 True + 反向对照 False（`calls=129`），图上 `f002` verified + operator confirmed。

**通用化**：① 「注册/登录/改密三件套」本身就是二阶注入信号——登录打不动 ≠ 没有注入，去找「二次使用点」。② oracle 不必依赖时间：任何「受 COND 影响的副作用」（如自己那行的密码变没变）都能当布尔判定，比自己脑补 sleep 盲注更稳。③ 写盲注脚本前先量约束（列长/过滤/转义），否则会把「技术限制」误判成「条件为假」。

### 密钥随校验脚本泄露的 AES-CBC：「解密后满足字节条件」→ 选明文重打，而不是逆解（Crypto / CBC 条件构造）

**触发条件**：题目给你一对 c1/m1（或任意明文-密文对）+ 一句「`m2 = decrypt(c2)` 的若干固定位置必须等于指定字节」，同时 **KEY/IV 出现在发给选手的附件里**（本例：服务端校验脚本《时间线.py》把 KEY/IV 硬编码在其中）；要求你交 c2。

**做法**：
1. **先把条件归到明文侧**：`m2[pos]==value` 约束的是**解密结果**。KEY/IV 已知时，任何满足条件的明文重新加密就是合法 c2 —— 不需要解 c1、不需要逆 AES（别往「已知明文攻击/反推密文」方向绕）。
2. **最小构造**：`m2 = bytearray(b'A'*256)`，把条件位置逐个写成目标字节；`c2 = AES-CBC(KEY,IV).encrypt(m2)`；`base64.b64encode(c2)` 一行提交（注意服务端常带 `validate=True` + 固定长度检查）。
3. **备选：CBC 位翻转**（只在「必须尽量保留原明文」时才值得用）——`P_i = D(C_i) ⊕ C_{i-1}`：要改 `m2[p]`，就把 `c1` 第 `⌊p/16⌋-1` 块的 `p%16` 字节异或 `old^new`。**先核对每条条件所在块**：
   - ★ **块 0（p<16）的条件翻不出来**：`P0 = D(C0) ⊕ IV`，动 `C0` 会把整块带入不可预测值，唯一通路是改 IV（一般不允许）→ 块 0 的条件只能靠重新加密达成；
   - ★ **翻一块会打乱它的前一块**：若「有条件的块」是连续的（本例 9 个条件恰好占满第 0..8 块、每块 1 个），则任何一次翻转都会破坏前一格里已有的条件 —— 单字节贪心翻转必然全盘失败；
   - 只有当「每个被改写的目标块的前一块都没有条件」时，朴素翻转才成立。
4. **交付前本地复解一遍** `decrypt(c2)`，逐条断言条件，再发远端。

**坐实**：✅ 本项目 flag 已解并平台确认 —— `0xGame{th15 15 my v1ct0ry}`（`board/projects/0xgame-ssh-timeline/`：`f002` verified、operator `confirmed`；`work/0xgame-ssh-timeline/evidence.txt` 留服务端逐字回显）。本题的「白盒」入口就是附件《时间线.py》里自带 KEY/IV。

**通用化**：条件落在哪一侧，决定问题形态 —— 条件在**明文**侧且密钥可得 ⇒ 「构造 + 重新加密」是零成本通路；条件在**密文**侧（或密钥未知、只给一对 c1/m1）才轮到翻转/差分。选路之前先把「每 16B 块里有几条条件」列成表，块 0 与相邻块的边界一眼就能判死位翻转方案。

**来源**：0xgame-ssh-timeline
