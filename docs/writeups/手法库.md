# 手法库（跨题积累）

> 黑板（`board/`）管**某一次**解题的真相；这里管**下一次能直接用的东西**。
> 由旁支代理（`skills/wp-writer/`）在解完题后蒸馏写入。
>
> **宁缺毋滥** —— 灌水的库下次就没人读了。
> 每条必须能回答：**看到什么信号该想到它**、**具体怎么做**、**从哪来的**。
> 没有真正可复用的东西就跳过，别硬凑。

记录格式：

```markdown
### <手法名>（<适用场景>）
**触发条件**：看到什么信号就该想到它
**做法**：具体步骤 / 命令
**坐实**：★ 用它**真拿到过什么**（flag 原文 / 洞 + 证据文件路径）—— **空口经验不算，宁可不写**
**来源**：<项目id>
```

> ★ **「坐实」这一栏是硬要求**（借鉴 Trail of Bits `skills` 的 **Trophy Case** 纪律：
> 它给每个技能挂「用它挖到的真实漏洞 + PR 链接」）。
> 为什么：对外谈能力要用**坐实的洞数**，不用「跑过多少题」。
> 一条手法写不出「坐实」，说明它还没被验证，**标 `未坐实` 而不是删**，下次优先试它。
