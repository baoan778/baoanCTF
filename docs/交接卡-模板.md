# 交接卡 + 开新对话判据（本仓适配版）

> 由来：2026-11-23 操作者拿来一份外部模板《AI 省额度与开新对话提醒模板》，问能不能改成我们自己的。
> 结论：**取两段、弃其余** —— 取「会话交接卡」与「该换会话了的触发判据」，
> 其余（只读片段、进度落盘、模型分级）本仓已有更硬的实现，或已被实测否定。
> 落地物：`tools/handoff_card.py`（命令 `handoff-card`）+ 本文件 + `board/tests/test_handoff_card.py`。

---

## 一、为什么需要它（缺口在哪）

| 现有机制 | 问题 |
|---|---|
| 旧的状态快照（整读等于先烧掉一次预算） | 一开头整读就等于先烧掉一次预算；真正要看的只有一小半 |
| `handover`（打整套交接包） | 面向**交付**（文档 + 留档 + 黑板 + 校验），太重，不适合每天开工 |
| `fgs checkpoint` 五段式 STATE | 面向**单题解题**的作战状态，不是仓库级交接 |
| 上下文压缩（阈值 12 万） | 治的是「同一会话太长」，**不管**「该开新会话了」 |

⇒ 缺的是**仓库级、机器生成、≤60 行**的开机读本，以及「什么时候该换会话」的机器判据。

## 二、交接卡（`handoff-card`）

### 口径（五条，写死在代码里）

1. **只输出机器能核对的事实**：git 分支/提交/未提交改动、解题账本、余额闸门、常驻提示词预算。
   缺数据写「缺」并说明原因，**不猜**。
2. **人写的判断只有一个来源**：黑板上的待办清单，**原样搬运不改写**
   （与 `board/handover.py` 的 `todo_verbatim()` 同一口径）。
3. **只读**：除 `--out` 指定的那一个文件外不写任何东西。
4. **有界**：读盘一律限长（单文件 2MB），超了报「太大」而不是吃内存。
5. **不冒充自检结论**：本卡不跑测试。要自检就跑 `selfcheck`。

### 用法

```bash
handoff-card                          # 打到 stdout，先看
handoff-card --out docs/交接卡.md     # 落盘给下一个会话读
handoff-card --json                   # 机器可读
handoff-card --check                  # 待办指纹与现场不一致 → rc=3（commit 不影响）
handoff-card --advise --session <jsonl>   # 按下面的判据给「该换会话了」的建议
handoff-card --max-lines 60           # 硬上限，超了按优先级截并明说截了什么
```

### 已踩过的两个坑（都是本工具自己的）

| 坑 | 现象 | 修法 |
|---|---|---|
| **空行被当成第 0 块** | 小节标题后通常空一行，`rows[0]` 是空串；无条件把 0 插进块起点 → 第 0 块是空行 → 整段待办渲染成「（待办为空）」，**比不给更误导** | 只有开头的**实质内容**才单独成块 |
| **按块内最大日期排序会挑错块** | §0.5 三块的块头是 10-11 夜 / 10-11 晚 / 10-10 晚（新到旧），但正文常夹着后来的「★ 2026-11-18 校正」批注 → 按最大日期排会把**最老那块**排第一 | 顺序信文件，时效只做提醒（算「这块最新提到哪天」+ 几天前） |
| **`--check` 比 HEAD 提交号会天天假红** | 卡刚生成、刚提交，只要再 commit 一次就判「过期」，检查很快会被人关掉 | 卡里记 **§0.5 正文的 sha256 前 12 位**（`todo:<hash>`）；只有人真改了待办才过期，commit 不影响 |

## 三、开新对话判据（`--advise`）

外部模板给的是**人肉自觉**的 5 条。这里改成**可算的信号**，每条都给证据：

| ID | 信号 | 阈值 | 为什么是这个数 |
|---|---|---|---|
| T1 | 用户轮次 | ≥ 30 | 外部模板的经验值；本仓会话实测中位远低于此 |
| T2 | 累计 token（input+cache+output） | ≥ 2,000,000 | R13 实测输入/输出 27:1，长尾会话 p95 峰值 6.8 万/轮；200 万约等于 30 轮满上下文 |
| T3 | 同一工具 + 同一入参重复次数 | ≥ 5 | **原地打转**的机器判据（本仓已有 `reflect.py` 判「同方法」，这条判「同一次调用」） |
| T4 | 账本累计花费 | ≥ $1.5 | 单题成本上限是 $0.45（R7-B），$1.5 ≈ 三题打完还不出就该换 |
| T5 | 距最后一条消息 | ≥ 6 小时 | 缓存多已过期，续跑按全价重读 —— 这时「回一句继续」最贵 |

### 提醒格式（照抄给人）

> ⚠️ 建议开新对话：<第一条触发原因>。交接卡已更新到 docs/交接卡.md。

### 边界（诚实标注）

- **阈值不是从本仓数据标定的**：T1/T2/T5 来自外部模板 + R13 的实测分布，属于**保守起点**；
  T3/T4 是本仓已有判据的复用。跑够样本后应回填（参照 R13 的做法：先给判据，再拿真实数据校正）。
- **`--advise` 不改任何文件**：它只输出建议，写卡要显式 `--out`。
- **没有自动挂到扩展上**：这是刻意保守 —— 触发一次误报就会打断解题节奏。
  想接线的话挂 `idle-resume` 的空闲通道（与 reflect-paper 同一套），别挂每轮。

## 四、没抄的部分（以及为什么）

| 外部模板的建议 | 本仓现状 | 处置 |
|---|---|---|
| 只读必需片段、不整读大文件 | `AGENTS.md` §三「大输出不许整读」更硬（head/wc/grep 三件套） | 不抄 |
| 每阶段进度写 `HANDOFF.md` | `fgs checkpoint` 五段式 STATE（<150 行）+ `handover` 已在 | 不抄，改成本卡的 §3 直接搬 §0.5 |
| 长对话很贵，缓存会过期 | R13 已量化（输入/输出 27:1、压缩 −57%），有成本账本 + `costguard` | 只取「6 小时」这一条做 T5 |
| **简单活用便宜模型** | **R11-02 A/B（各 48 次）实测：降档不快且贵 11.1%** | **明确不抄**（与实测冲突） |
| 一个任务一个对话 | `AGENTS.md` §六 多轮任务用黑板（FGS），比开新对话更省 | 不抄 |
