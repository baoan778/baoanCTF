## 零、一句话结论

> **Agent 之间不通信，只读写同一块黑板；黑板是唯一真相；
> 写入必须经过校验；结论必须分级；超时也要留下足迹；
> 一开始别规划，先动手。**

Cairn 拿 AK（610 队里唯一 54/54）那套东西里，**没有一行是"更聪明的 prompt"** ——
全是**结构**上让浪费不可能发生。

三个来源各司其职：

| 项目 | 贡献 | 权重 |
|---|---|---|
| **oritera/Cairn** | 主架构：黑板 + 三原语 + 三类任务 + 唯一写入者 + 双阶段 | ★★★★★ |
| **n1majne3/CyberPenda** | 收敛形态：Goal/Step/Fact + 11 种受限关系 + Outbox/校验分离 | ★★★★★ |
| **QiantangCredit/heimdall-agent** | Solver / Observer / Summarizer 三组 prompt 分离 | ★★★ |
| **Yean-Sec/StrikeAgent** | 记忆蒸馏 + 二次评级验证 | ★★★ |
| **Ch1nfo/RiftX** | 编排无新概念，但**离线资料库 3.8MB** 被第一轮漏掉 | ★★★（资料层） |

## 一、oritera/Cairn —— 主架构来源

### 成绩

| 指标 | 值 |
|---|---|
| 赛题 | 腾讯云黑客松 · AI 渗透测试挑战赛（第 2 期） |
| 规模 | 610 队 / 1345 人 · 全国高校与安全厂商 |
| 解题 | **54 / 54 —— 唯一 AK 队** |
| 名次 | 第 3 |
| 备注 | **赛前从未测过**，完整链路比赛日凌晨 4 点才首次上线。零 MCP、零 RAG、零预设角色 |

### 核心命题（这段是整份文档最值钱的部分）

> 渗透测试本质是**在近乎无限的状态空间里做有向搜索**：
> **起点已知**（目标 IP / 目标系统）、**终点已定义**（拿 shell / 拿 flag）、**路径未知**。
>
> 这个结构不只属于渗透 —— 漏洞研究、数学证明、CTF 都是同一个形状。
> Cairn 是为这一类问题造的引擎。渗透是它第一个被验证的领域。
>
> —— Cairn 自我定位：*"defines no roles, no workflows. Given an origin and a goal,
> it searches for a path through an unknown state space."*

**推论**：既然路径未知，那么**预先规划就是伪工作**。这是后面 `bootstrap` 任务存在的根本理由。

### 三原语

| 概念 | 含义 |
|---|---|
| **Fact** | 一个已确认的、客观的发现，写进黑板 |
| **Intent** | 一个已声明但还没执行的探索方向 |
| **Hint** | 人的判断，随时注入，agent 下次读图时吸收 |

> 图从 `origin` 长向 `goal`。
> **每个新 Fact 是一块垫脚石，每个 Intent 是向未知迈出的一步。**

### 三类任务（同一个 Worker 执行，无固定角色）

| 任务 | 干什么 | 产出 |
|---|---|---|
| `bootstrap` | 项目开始时**直接尝试解决整个问题** | Fact + 可能的 Complete |
| `reason` | 读**全图**：目标达成了吗？下一步该探索什么？ | Complete / 新 Intent / 空操作 |
| `explore` | 认领**一个** Intent，执行，报告发现 | 一个 Fact |

**关键设计：任务从图状态在运行时生成，不是从预设的岗位描述来的。**

### 系统架构

```
        ┌──────────────────────────────────┐
        │           Cairn Server           │  ← 协议真相源（只维护图一致性）
        │    Facts + Intents + Hints       │
        └─────────────────┬────────────────┘
                          │  Read / Write API
        ┌─────────────────┴────────────────┐
        │             Dispatcher           │  ← 唯一协议写入者
        │   调度任务 / 管容器 / 写回协议     │
        └──────────┬───────────────┬───────┘
                   │               │
       ┌───────────┴──┐     ┌──────┴──────────┐
       │ Worker 容器A │     │  Worker 容器 B   │
       │  ┌──┐  ┌──┐  │     │  ┌──┐  ┌──┐      │
       │  │W │  │W │  │     │  │W │  │W │      │
       └──────────────┘     └─────────────────┘
```

**最硬的约束**：

> Agent **不**直接认领 Intent、**不**直接 heartbeat、**不**直接调用 Cairn API。
> 只接收 Dispatcher 下发的任务，返回结构化 JSON；
> 由 Dispatcher 决定怎么请求 Server。

> **Agent 之间只通过黑板协作（Stigmergy）。不直接通信。没有信息孤岛。**

### 双阶段（execute + conclude）

`bootstrap` 和 `explore` 都是两阶段。第一阶段超时或输出解析失败时：

1. 杀掉进程，**保留 session id**
2. 保持 heartbeat，用**同一个 session** 进入 `conclude`
3. `conclude` 的 prompt 必须明确要求「**不要继续探索，只总结截至目前的结论**」
4. 只产出一个 Fact

> 理由：探索了十分钟被超时砍掉、结果一个字都没留下，是最没意义的浪费。

### 我照搬的

1. 黑板是唯一共享真相；Worker 不互相通信
2. `bootstrap` 只在初始态跑，**直接解决而不是先规划**
3. `reason` 的"新态势"去重规则（Fact/Hint 数增加、或从有 open 变成没有）
4. Dispatcher 是唯一协议写入者 → pi-lab 里主会话是唯一写图者，Worker 只能投 outbox
5. 双阶段 `execute + conclude`
6. Prompt 以 markdown 分发、带占位符、按组切换
7. 退出码语义化（`SUBMIT_BUSY` ≠ 答错 —— 这类区分省掉大量浪费）
8. 健康检查打**真实 API**，不只看"容器活着"

### 我没照搬的

| 没抄 | 为什么 |
|---|---|
| Docker 容器隔离 | pi-lab 是单机，`work/<pid>/` 目录隔离够用，还更好查 |
| 多 Worker 并发池 + priority/max_running | pi 的 subagent 已提供，不重复造 |
| HTTP Server + SQLite | 单机单写者，文件 + 原子替换更简单也更好审查 |

## 二、n1majne3/CyberPenda —— 收敛形态来源

Go 实现，**运行时就是 pi**（有 `pi-runtime`、pi-subagents 仓里的 `docs/research/`）。
37 篇 ADR 记录了从 Cairn 概念一路演进的全过程 —— **这是最值钱的参考**。

### 关键演进路线（我跟着走的）

| ADR | 决定 | 对我的影响 |
|---|---|---|
| 0003 | 用项目级**语义化黑板键** | 节点用 `g001`/`s003`/`f012` 而不是随机 uuid —— 人和模型都能读 |
| 0005 | **任务目标不进黑板** | Goal 属于项目不属于任务 |
| 0006 | 存**带版本号的语义状态**，不存事件账本 | `graph.json` 是真相，`log.jsonl` 只是给人看的审计 |
| 0007 | **原子重建**黑板 | 写 tmp 后 `os.replace`，不留半写状态 |
| 0009 | 从**黑板状态**恢复，不从任务摘要恢复 | 重启后读图就能继续，不依赖对话历史 |
| 0010 | **删掉** observation / hypothesis 记录类型 | 别搞半成品类型 |
| 0011 | 删掉 project directive 记录 | 同上，**做减法** |
| 0012 | **11 种受限关系 + 端点矩阵** | 全部照搬 |
| 0018 | **把工作轮次和调度控制轮次分开** | 主循环归主循环，解题归解题 |
| 0021 | 把"结论义务"与"派发"分开 | `conclude` 是独立阶段，不是执行的附带品 |
| 0032 | 用 working graph 替换 assisted blackboard | 图是工作记忆，不是辅助记录 |
| **0035** | **用 FGS 做黑板工作模型** | ★ **Goal / Step / Fact 就是最终形态** |
| 0035 | Runtime 通过 **Outbox** 发布，Harness 校验传输与权限 | ★ 照搬成 `publish` / `apply` |

### ADR 0035 原文核心（建议背下来）

> 用 Goal、Step、Fact 直接做黑板。
> **Goal、Step、Fact 是唯一的节点类型。**
> 移除 Entity、Finding、Solution、Evidence Artifact 作为目标图节点类型。
>
> Runtime 遵循 Harness 投影到 AGENTS.md 的 FGS 指令，自己决定做什么。
> **不需要调用 FGS Skill。** 它通过 Outbox 发布结构化更新。
> Harness 校验传输与权限，黑板服务校验并存储。
>
> 启动消息给出明确启动序列：
> **读指令 → 读已接受状态 → 发布 Goal 与第一个 Step → 检查回执。**
>
> **已接受的黑板状态才是持久共享图。Runtime 文件只是本地工作状态。
> 一个没提交的本地编辑不是黑板更新。**
>
> 用当前语义状态 + 紧凑语义历史 + 持久投递回执。
> **Outbox 投递格式不是黑板存储格式。**

还有那条最扎心的（讲的是**缺失的回报闭环**）：

> 一个真实 Session 初始化了图，然后在原生 Task 和一个独立队列里推进工作。
> 它的状态文件在网络故障恢复、Fact 已记录之后**仍然报着失败** ——
> 这暴露的是**缺一个回报闭环**，
> **不是**说明 Harness 必须变成 agent 调度器。

### 我照搬的

1. **三节点收敛**（Goal/Step/Fact），不做七节点 —— 后来删掉的那些类型是明确的教训
2. **11 种关系 + 端点矩阵**，非法组合直接拒
3. **原子替换状态文件** + 语义状态为真相、流水仅审计
4. **Outbox / apply 分离** —— 本设计里最重要的安全边界
5. 节点**语义化 id**，路径用 `projects/<id>/`
6. ADR 里反复出现的"**做减法**"倾向（0010/0011/0032/0033 全是在删东西）

### 第二轮精读（0021 / 0022 / 0023 / 0024 / 0034 / 0036 / 0037）—— 都是**已落地**的

第一轮读的是概念面；第二轮补的是 0020 段之后与它自己的 `docs/specs/`。七篇里有四篇直接改了 pi-lab 的代码：

| ADR | 它说的 | pi-lab 落成什么 |
|---|---|---|
| **0021** | 结论义务与投递尝试分离；只有活跃 dispatch 能 apply；迟到的结果只能是终态投递结论，**不能改变黑板状态** | `deliveries.jsonl` 投递台账 + `duplicate` 终态（同指纹不二次写图） |
| **0023** | Accepted 最终必须 settle 为 `applied/failed/action_required`；**预算属于义务、不随新尝试重置**；禁止通用重试 | 四种终态 + `attempts` 计数 + `fgs outbox` 视图 |
| **0034** | 首灯身份检查 + leader.lock 单 epoch 心跳；孤儿会话应**降级为 worker**而不是自封第二个 orchestrator | `lead.json` + `fgs next` 的自动接管 / exit 2 停手 |
| **0037** | 把离线知识基线烤进镜像（HackTricks / PayloadsAllTheThings / SecLists 精选） | `tools/knowledge/`（RiftX 资料库 + NOPTrace 手册）+ `INDEX.md` |
| 0022 | finish 只是 intent，等 turn settle 才生效；同轮后续工作使 intent 失效 | 映射成纪律：**conclude 必须发生在探索停止之后**，双阶段不重叠 |
| 0024 | 投影要有界：导航不随历史增长，历史窗口按条数与字节数封顶 + 向后分页 | **分层采纳**：图（工作记忆）保持拓扑完整，`fgs log --tail` / `fgs outbox --tail` 有界 |
| 0036 | 子代理会话独立分页，主 transcript 只要摘要 + 引用 | 派子代理只要一行回执（`async: true` 不阻塞、不轮询） |

**0024 与 Cairn 的张力**（值得记住）：Cairn 说「给 Worker 的快照必须拓扑完整，不许裁剪」，
0024 说「投影要有界」。两者都对 —— 区别在**对象不同**：**图是工作记忆，必须完整；
历史与流水是审计，必须有界**。pi-lab 按这个分层，不是二选一。

### 我没照搬的

- ACP / Hermes 多 runtime 协议（pi-lab 只用 pi）
- 关系元数据版本化到 `(source key, type, target key)` 那一层（单机不需要）
- 37 篇 ADR 的完整治理流程 → 收敛成一份 `board/schema.md`

## 三、heimdall-agent —— 观察者分离

定位：CTF / 授权安全靶场的自主 agent 框架，「Circle of Circles · Execute, observe, and keep exploring」。

### 借的点

`resources/prompts/` 分成三组：

| 组 | 作用 |
|---|---|
| `solver/` | 干活：`protocol.md` `user.md` `loop_followup.md` |
| `observer/` | **旁观者**：`observer_system.md` `observer_spray.md` `observer_recap.md` |
| `summarizer/` | 只做摘要，不干活 |

其他：
- `resources/workspaces/types/{web,cve,pwn,intranet,evasion,all}/CLAUDE.md` —— **按题型给不同的工作区指令**
- `resources/skills/catalog/` + `mapping.json` —— 技能目录 + 映射表
- `docs/runtime-reliability.md`（CyberPenda）—— 运行时可靠性单独成篇

### 落成什么

- `reason` 本质就是 **observer**
- prompt 分组 → 我用 `fgs-` 前缀区分任务
- **没做**按题型分工作区指令：题型知识已经落在 `skills/ctf-*/` 里了，不重复

## 四、StrikeAgent —— 记忆蒸馏与二次验证

**Tsecbench v1 第 1 名（97.89 / 100）**，腾讯安全云鼎实验室的智能攻防 Agent 评测。
运行时也是 pi（`agents/pi_runtime.py`）。定位明确：**只做外网打点**，
"专注于一点登峰造极"（团队自用 Pro 版已落地几十个项目、超千个真实授权环境）。

### 借的点 ①：记忆蒸馏

> 收工把手法蒸馏进记忆库。

相关模块：`memory/evolve.py`、`generalize.py`、`methodology.py`。

一轮打完之后，把"这次是怎么打通的"**抽象成可复用的手法**存起来。
**和黑板是互补的**：

| | 管什么 | 生命周期 |
|---|---|---|
| 黑板 `board/` | **这一次**解题的真相 | 单项目 |
| 手法库 `docs/writeups/手法库.md` | **下一次**能直接用的东西 | 跨项目 |

### 借的点 ②：红队二次评级 + 二次验证

> 为了避免 AI 给出的漏洞存在夸大或误报的情况，团队特别设计了红队二次评级和二次验证，
> 让漏洞所见即所得、拿着就能用。

**直接对应我们的 `confidence` 分级**：`verified` 必须独立复现过一次，
不是"跑通了看着像"。

这条在 pi-lab 里演化成了**两道门**：

| 门 | 命令 | 谁下 |
|---|---|---|
| 1 | `fgs solved` | agent 自评 |
| 2 | **`fgs confirm`** | **人看过平台回显** |

**对外产物（WP）只认第二道门** —— 不能建立在 agent 的自我评价上。

### 其他可参考的

- `graph/` —— 独立攻击图模块，含 `hypothesize.py` / `verify.py` / `rating_rubric.py`（**有评级标准**）
- `engine/` —— `loop.py` / `scheduler.py` / `spiral.py` / `hunt_clock.py` / `turn_close.py`
- `scope.py` / `scope_pivot.py` —— 授权范围与横向移动的边界管理
- `report/` —— 交付报告生成（HTML/PDF）

> **"从者整轮打完再问御主"** 这条照搬了：子代理只在**收口时**回报一次，
> 不是每一步都回来打断 —— 也就是我们的**双阶段 + outbox** 设计。

## 五、RiftX —— 不是编排来源，是**资料库**

第一轮只看了它的目录结构，判「没有引入 Cairn 之外的新概念」—— 这个判断**只对了一半**。
第二轮（`refs-gap` 项目）把它整个 `recommended-skills/` 读了一遍，结论分两半：

### 编排层：确实无新概念

Next.js/TS 的渗透工作台（`bin/rx.mjs` + playwright + 自己的 `browser navigate` / `record_finding` API）。
它那套运行时工具调用语法**本机没有**，也没必要有 —— 我们用的是 pi 的 subagent + 黑板。

### 资料层：**被漏掉的 3.8MB 实料**

```
recommended-skills/  36 个 skill，SKILL.md 合计 1929 行
  ├─ references/  32 个目录、68 篇 md（idor-deep 578 行、cache-poisoning 1297 行、
  │               request-smuggling 1342 行、ghost-bits-cast 743 行、deserialization 1217 行…）
  ├─ assets/       9 个目录、81 个 payload txt（SQLi 报错/时间盲注、DBMS 指纹、
  │               路径穿越文件名、CSP 绕过、mutation XSS…）
  └─ scripts/      8 个目录、30 个 py（boolean_sqli_tester、sqli_payload_generator、
                  response_analyzer、lfi_exploiter、xss_full_scan…）
+ security-* 字典：NCSC 10 万口令 / probable-v2 top12000 / darkweb2017 top10000 / 用户名字典
```

**里程碑判断**：它的价值不在"架构"，在**按攻击面切分的粒度** —— recon-* 5 / exploit-* 21 /
security-* 5，一个攻击面一个 skill，各自带 references + assets + scripts。

### 我照搬的（以及**故意没照搬**的）

**照搬**（`tools/knowledge/riftx/`，MIT 许可）：

1. `references/` + `assets/` + `scripts/` 全量落地，作为**离线知识基线**
   （对应 CyberPenda ADR 0037 的设计意图）
2. `INDEX.md` 由 `build-index.py` 生成：36 条「用途 → 对应 pi-lab 哪个 skill」
3. `skills/src-recon/` 与 `skills/ctf-web/` 各加一张**按攻击面直达**的取用表
   （卡在越权就翻 `idor-deep.md`，卡在 PHP 弱类型就翻 `php-magic-hashes.txt`）

**没照搬**：**不新切 36 个 skill**。
照搬粒度会直接违反 CyberPenda 那条「做减法」（0010/0011/0032/0033 一半 ADR 在删东西）。
pi-lab 只有 `src-recon` + `ctf-web` 两个 Web 类 skill，靠**一张索引表**把 36 个攻击面接进来 ——
入口数量保持少，可发现性靠索引解决。

### 可迁移原则

> **"技能数量"不是能力，可发现性才是。** 36 个 skill 如果没人知道该翻哪个，等于没有；
> 2 个 skill + 一张按攻击面组织的索引，反而更好用。

## 八、可迁移的设计原则

从这五个项目里能抽出来、**脱离安全领域也成立**的原则：

1. **状态空间思维**：起点 + 终点 + 未知路径 ⇒ 预先规划是伪工作，先动手让事实教你规划
2. **黑板（stigmergy）**：协作者不互相通信，只读写共享环境 —— 避免信息孤岛，也让零上下文接手成为可能
3. **唯一写入者**：写入经过一个校验点，单个参与者的幻觉不会污染全局
4. **结论分级**：`verified` / `inferred` / `unverified` 必须区分，**只有前者能当结论**
5. **人的判断单独成一条通道**（Hint / confirm）：不要混进 agent 的自我评价
6. **超时也要留下足迹**（双阶段 conclude）：没解决问题 ≠ 没有产出，"试过哪条路、看到什么"本身就改变搜索空间
7. **语义状态为真相，流水仅审计**：不要用事件账本当主存储
8. **原子重建**：任何覆盖写都要 tmp + rename，永远不留半写状态
9. **去重按"态势"不按"变化"**：`reason` 只在有新 Fact/Hint 时才重跑，否则会自激
10. **做减法**：CyberPenda 一半的 ADR 在删自己之前加的东西；类型越少，推理越稳
11. **给协作双档**：`context: fresh`（不 fork 上下文）既是省 token，也是**记录质量的自检** ——
    零上下文的人读图还原不出过程，说明图记得不够
12. **自动判据要 fail-closed，不要把"调阈值"当成解法** ——
    手法库去重闸门的实测教训：精确标题比对 → 漏；正文子串 → 漏；等权 token 覆盖率（阈值 40%）→
    还是漏（中文 bigram 噪声把真实相似度压到 34%）。**三次都真的写进了重复条目**。
    结论不是"再把阈值调低一点"，而是把默认姿态换成
    **"只要有可察觉的重合就拦下，要写必须由人显式 `--force-dup`"**：
    漏判的代价是数据不可逆地变脏，误拦的代价只是多敲一个 flag。
